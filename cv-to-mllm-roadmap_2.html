🔥 核心概念

前向传播（Forward Pass）：输入 x → 逐层计算 → 输出预测 ŷ。每一层做的事本质上就是 output = activation(W · input + b)。

损失函数（Loss）：衡量预测 ŷ 和真实标签 y 的差距。分类用交叉熵 CrossEntropyLoss，回归用均方误差 MSELoss。

反向传播（Backpropagation）：用链式法则从损失往回算每个参数的梯度 ∂L/∂W，然后用梯度下降更新参数。

📐 推导 链式法则与梯度下降（手推一遍加深理解）
两层网络 · 前向
$$\begin{aligned} z_1 &= W_1 x + b_1, \qquad h = \mathrm{ReLU}(z_1)\\ z_2 &= W_2 h + b_2, \qquad \hat{y} = \mathrm{softmax}(z_2)\\ L &= -\textstyle\sum_i y_i \log \hat{y}_i \quad(\text{cross-entropy}) \end{aligned}$$
反向 · 链式法则（从后往前）
$$\begin{aligned} \frac{\partial L}{\partial z_2} &= \hat{y} - y\\[2pt] \frac{\partial L}{\partial W_2} &= \frac{\partial L}{\partial z_2}\, h^\top, \qquad \frac{\partial L}{\partial h} = W_2^\top \frac{\partial L}{\partial z_2}\\[2pt] \frac{\partial L}{\partial z_1} &= \frac{\partial L}{\partial h} \odot \mathrm{ReLU}'(z_1)\\[2pt] \frac{\partial L}{\partial W_1} &= \frac{\partial L}{\partial z_1}\, x^\top \end{aligned}$$

关键：$\dfrac{\partial L}{\partial z_2}=\hat{y}-y$ 是 softmax + 交叉熵组合后的简洁梯度；$\odot$ 为逐元素乘。

参数更新 · 梯度下降
$$W \;\leftarrow\; W - \text{lr}\times \frac{\partial L}{\partial W}$$

常用优化器：SGD（最基础）· Adam（自适应学习率，最常用）· AdamW（Adam + 权重衰减，大模型标配）。

🗣️ 大白话 · 把这套流程想成一次考试：前向 = 你做完题、交出答案；损失 = 老师批改，告诉你一共扣了多少分；反向传播 = 老师沿着你的解题步骤倒着追责，指出「你这一步贡献了多少扣分」（这就是梯度）；梯度下降 = 你照着每步该改的方向和幅度，把解法修正一点点。链式法则就是「从最终扣分往回，一层层算每层该背多少锅」—— 深度学习的全部训练，不过是把这场考试重考几百万遍。

动手：用 numpy 手写一次前向 + 反向

import numpy as np def softmax(z): e = np.exp(z - z.max()); return e / e.sum() def forward(x, W1, b1, W2, b2): z1 = W1 @ x + b1 h = np.maximum(0, z1) # ReLU z2 = W2 @ h + b2 yhat = softmax(z2) return yhat, (x, z1, h) def backward(y, yhat, cache, W2): x, z1, h = cache dz2 = yhat - y # softmax + CE 的简洁梯度（对照推导） dW2 = np.outer(dz2, h) dh = W2.T @ dz2 dz1 = dh * (z1 > 0) # ReLU' = (z1>0) dW1 = np.outer(dz1, x) return dW1, dW2 # 训练一步：前向 → 反向 → 梯度下降 x, y = np.random.randn(4), np.eye(3)[1] W1,b1,W2,b2 = np.random.randn(8,4),np.zeros(8),np.random.randn(3,8),np.zeros(3) yhat, cache = forward(x, W1, b1, W2, b2) dW1, dW2 = backward(y, yhat, cache, W2) W1 -= 0.1 * dW1; W2 -= 0.1 * dW2 # W ← W − lr·∂L/∂W # 看懂这 20 行，你就懂了所有深度学习训练的本质
🔬 复现实验 · 梯度检查

怎么确认你手写的反向是对的？用数值梯度当裁判：把某个参数微微加减一点 $\epsilon$，看 loss 的变化，$\frac{L(w+\epsilon)-L(w-\epsilon)}{2\epsilon}$ 就是该参数的近似梯度，它应当和你解析推导的梯度几乎相等。这是每个做深度学习的人都该会的自检，也正是 PyTorch torch.autograd.gradcheck 的原理。

# 数值梯度 vs 解析梯度（接上一段的 W1,b1,W2,b2,x,y,dW1）：两者应一致到 ~1e-7 def loss_of(W1, b1, W2, b2, x, y): z1 = W1 @ x + b1; h = np.maximum(0, z1) z2 = W2 @ h + b2; p = np.exp(z2 - z2.max()); p = p / p.sum() return -np.log(p[y.argmax()] + 1e-12) eps = 1e-5; num_grad = np.zeros_like(W1) for i in range(W1.shape[0]): for j in range(W1.shape[1]): up = W1.copy(); up[i, j] += eps dn = W1.copy(); dn[i, j] -= eps num_grad[i, j] = (loss_of(up,b1,W2,b2,x,y) - loss_of(dn,b1,W2,b2,x,y)) / (2*eps) rel = np.abs(num_grad - dW1).max() / (np.abs(num_grad).max() + 1e-12) print(f"max relative error = {rel:.2e}") # 预期 < 1e-6 → 你的反向是对的
梯度检查是「你真的懂反向传播」的硬指标；过不了，下面调试实录第 ①② 条对号入座。

📑 工业实证 · 大厂战报

你这 20 行不会炸，但放大到千亿参数，「梯度 → 更新」这一步会出大事。GLM-130B、PaLM、OPT-175B 在预训练时都反复遭遇 loss spike（损失毫无征兆地突然飙升甚至发散）。

怎么救：PaLM / OPT 的土办法是回滚到尖峰前的 checkpoint、跳过那几个 batch 再继续；GLM-130B 团队进一步定位到是 embedding 层的异常梯度在作怪，提出「embedding gradient shrink（缩小词嵌入梯度）」显著稳住了训练。一句话：今天你理解的「梯度 → 更新」，正是大模型训练里最脆弱、最烧钱的环节。

来源：GLM-130B（arXiv:2210.02414） · PaLM（arXiv:2204.02311）
🐛 调试实录 · failure modes

① 梯度检查过不了：八成是转置写反（W2.T @ dz2 还是 dz2 @ W2）或漏乘激活导数（ReLU 的 (z1>0)）→ 逐层对维度、对推导。

② loss 变 NaN：softmax 没减最大值导致 exp 溢出 → 用 exp(z - z.max())；或 log(0) → 加 1e-12。

③ loss 不降反而乱跳：学习率太大 → 调小 lr，或换 Adam / AdamW。

④ 用 PyTorch 后 loss 越跑越怪：忘了 optimizer.zero_grad()，梯度跨 step 累加 —— 新手头号 bug。

🔥 CNN 三个关键概念

卷积核（Kernel/Filter）：一个小的可学习矩阵（如 3×3），在输入图像上滑动做局部特征提取。参数共享 + 局部连接 = 大幅减少参数量。

特征图（Feature Map）：一个卷积核滑过整张图后生成一张特征图。多个卷积核 = 多个特征图 = 多通道输出。

残差连接（ResNet）：output = F(x) + x。让网络学习残差而非完整映射，解决深层网络训练困难的问题。这个思想在 Transformer 的每一层都在用！

🗣️ 大白话 · 卷积核像一枚小印章：拿同一枚印章在整张图上到处盖，找同一种花纹（这就是「参数共享」—— 不必每个位置都学一套）。特征图就是盖完一种印章后得到的「哪里有这种花纹」的地图；换 N 枚印章就得 N 张地图。残差连接则是给网络修一条抄近路的高速路：万一这几层没学到有用东西，就先把原样 x 原封不动传过去，保证「越深至少不越差」—— 这正是能把网络堆到上百层的关键。

📐 推导 卷积操作的数学定义与输出尺寸计算
2D 卷积（单通道简化版）

输入 $X \in \mathbb{R}^{H\times W}$，卷积核 $K \in \mathbb{R}^{k\times k}$，输出特征图：

$$Y[i,j] \;=\; \sum_{m}\sum_{n} X[i+m,\;j+n]\cdot K[m,n]$$
输出尺寸（面试常考）
$$H_{\text{out}} \;=\; \frac{H_{\text{in}} - k + 2\,\text{padding}}{\text{stride}} + 1$$

例 ① 输入 $224\times224$、核 $3\times3$、padding $=1$、stride $=1$：$\,H_{\text{out}}=\frac{224-3+2}{1}+1=224$（尺寸不变）

例 ② 输入 $224\times224$、核 $7\times7$、padding $=3$、stride $=2$：$\,H_{\text{out}}=\frac{224-7+6}{2}+1=112$（尺寸减半）

多通道卷积

输入 $C_{\text{in}}$ 个通道，单个卷积核大小 $=C_{\text{in}}\times k\times k$；$N$ 个卷积核 → 输出 $N$ 个通道。

参数量 $=\; N \times C_{\text{in}} \times k \times k \;+\; N$（末项 $N$ 为 bias）

import torch, torch.nn as nn class ResidualBlock(nn.Module): # ResNet 的最小单元 def __init__(self, c): super().__init__() self.conv1 = nn.Conv2d(c, c, 3, padding=1) self.conv2 = nn.Conv2d(c, c, 3, padding=1) self.relu = nn.ReLU() def forward(self, x): out = self.conv2(self.relu(self.conv1(x))) return self.relu(out + x) # ★ F(x) + x，残差连接 x = torch.randn(1, 64, 56, 56) print(ResidualBlock(64)(x).shape) # torch.Size([1, 64, 56, 56])，尺寸不变 # 验证尺寸公式 H_out=(H−k+2p)/s+1 conv = nn.Conv2d(3, 16, kernel_size=7, stride=2, padding=3) print(conv(torch.randn(1,3,224,224)).shape) # [1,16,112,112]，尺寸减半
🔬 复现实验 · ResNet 退化现象

ResNet 最经典的一张图，你可以亲手复现：在 CIFAR-10 上训一个 56 层的「plain 网络」（无残差）和一个 20 层 plain 网络，会看到反直觉的一幕 —— 更深的反而训练误差更高（注意是训练误差，不是过拟合！）。再给它们加上残差连接，结论立刻翻转：56 层反超 20 层。

# nano-mllm/vision/degradation_demo.py —— 复现 ResNet 的「退化现象」 import torch, torch.nn as nn # 关键开关：use_res=False 是 plain 网络，True 是 ResNet class Block(nn.Module): def __init__(self, c, use_res): super().__init__() self.f = nn.Sequential(nn.Conv2d(c,c,3,padding=1), nn.BatchNorm2d(c), nn.ReLU(), nn.Conv2d(c,c,3,padding=1), nn.BatchNorm2d(c)) self.use_res, self.relu = use_res, nn.ReLU() def forward(self, x): out = self.f(x) if self.use_res: out = out + x # 唯一区别就这一行 return self.relu(out) def make_net(depth, use_res): # depth≈层数，堆若干 Block body = [Block(16, use_res) for _ in range(depth // 2)] return nn.Sequential(nn.Conv2d(3,16,3,padding=1), nn.BatchNorm2d(16), nn.ReLU(), *body, nn.AdaptiveAvgPool2d(1), nn.Flatten(), nn.Linear(16,10)) # 分别训练 make_net(20,False) / make_net(56,False) / make_net(56,True)，比它们的「训练误差」
同样深度，差别只在那一行 out + x。盯「训练误差」而非测试误差，才能确认这不是过拟合。

📑 工业实证 · 大厂战报

「加层反而变差」不是 bug，是 2015 年震动整个领域的发现。He 等人在 ResNet 论文里指出：56 层 plain 网络在 CIFAR-10 上的训练误差高于 20 层 —— 既不是过拟合、也不全是梯度消失，而是深层堆叠本身难以优化。一行 F(x)+x 把它解决了，从此网络能堆到 100+ 层，残差也成了所有现代架构（含 Transformer）的标配。

反转彩蛋：很多人以为 ViT 之后「CNN 已死」。2022 年 ConvNeXt 证明：把 ViT 时代的训练配方搬回纯 CNN，它能打平甚至超过同级 Swin Transformer —— 决定胜负的往往是训练方法，不只是架构。

🐛 调试实录 · failure modes

① out + x 形状不匹配报错：当通道数变了、或 stride>1 下采样了，x 与 F(x) 尺寸对不上 → 给跳连加一个 1×1 卷积（带相同 stride）做投影。

② 很深的网络 loss 不降：多半漏了 BatchNorm；ResNet 里 conv 后几乎必跟 BN。

③ 输出尺寸算错：padding / stride 没代进 $H_{\text{out}}=(H-k+2p)/s+1$ → 逐层打印 .shape 核对。

④ 显存爆 / 速度慢：浅层特征图分辨率高最吃显存 → 早点用 stride 或池化下采样。

📐 推导 注意力机制完整推导（最重要的推导之一）
核心直觉

注意力回答：每个位置该「关注」谁？类比在图书馆找书 —— Q=你要找的主题、K=每本书的标签、V=书的实际内容；用 Q 与每个 K 比相关度 → 加权提取 V 的内容。

Scaled Dot-Product Attention

输入 $Q\in\mathbb{R}^{n\times d_k},\ K\in\mathbb{R}^{m\times d_k},\ V\in\mathbb{R}^{m\times d_v}$，四步：

$$S = QK^\top \in \mathbb{R}^{n\times m} \;\xrightarrow{\;\div\sqrt{d_k}\;}\; A = \mathrm{softmax}(S) \;\longrightarrow\; \mathrm{Output} = AV \in \mathbb{R}^{n\times d_v}$$ $$\boxed{\ \mathrm{Attention}(Q,K,V) = \mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V\ }$$

为什么除以 $\sqrt{d_k}$：$d_k$ 较大时点积方差 $\approx d_k$，softmax 易饱和成 one-hot、梯度消失；缩放让方差回到 1。$A$ 每行和为 1，即每个 query 的注意力权重。

Multi-Head Attention

单头只能学一种关注模式；多头并行关注不同方面（语法 / 语义 / 位置…）：

$$\mathrm{head}_i = \mathrm{Attention}(QW_i^Q,\,KW_i^K,\,VW_i^V),\qquad \mathrm{MultiHead} = \mathrm{Concat}(\mathrm{head}_1,\dots,\mathrm{head}_h)\,W^O$$

$h$ 个头，每头维度 $d_k = d_{\text{model}}/h$。例：$d_{\text{model}}=768,\ h=12 \Rightarrow$ 每头 $64$ 维。

🗣️ 大白话 · 注意力就是「带着问题去查资料」：每个词拿自己的问题 Q，去和所有词的标签 K 比谁相关，再按相关度把对应内容 V 加权抄过来。除以 √d_k 是怕分数差距被拉得太悬殊、变成「赢家通吃」只盯一个词，缩放一下让它别太极端。多头像同一句话请 8 个不同专业的人各读一遍 —— 一个盯语法、一个盯指代、一个盯时间关系 —— 最后把各自理解拼起来。代价是 O(N²)：每个词都要和其他所有词「握一次手」，词一多，握手次数平方级暴涨（这正是后面 token 压缩、FlashAttention 要解决的痛点）。

🔥 Self-Attention vs Cross-Attention

Self-Attention：Q、K、V 都来自同一个序列。每个 token 看序列中所有其他 token。ViT 和 GPT 的核心。

Cross-Attention：Q 来自一个序列，K/V 来自另一个序列。用于不同模态之间的交互（后面多模态会用到）。

📑 工业实证 · 大厂战报

一个直接源于今天「softmax 必须和为 1」的诡异现象：attention sink。人们发现，训练好的 LLM 会把大量注意力莫名其妙地倒给第一个 token（哪怕它只是个无意义的起始符）。原因正是 softmax —— 当某个 query「其实谁都不太想看」时，那一份权重也总得花掉，于是模型学会一个「停车位」：把用不掉的注意力全停到开头几个 token 上。

这不是 bug，反而能利用：StreamingLLM 发现，只要在滑动窗口里永久保留最前面 4 个 token 的 KV，模型就能稳定处理 400 万+ token 的超长流式输入而不崩。理解了今天的 softmax，你就理解了这个支撑长上下文推理的工程技巧。

🐛 调试实录 · failure modes

① softmax 维度搞错：必须对「每个 query 的所有 key」那一维归一（dim=-1）；错成对 query 维归一，结果全乱却不报错 —— 最隐蔽的 bug。

② GPT 训练「作弊」、loss 低得离谱：忘了 causal mask，模型偷看了未来 token → 把未来位置分数设成 -inf 再 softmax。

③ mask 用 0 而不是 -inf：要在 softmax 之前 加 -inf（或 -1e9）才能让该位置权重归零；softmax 之后乘 0 是错的。

④ 忘了缩放 → NaN / 不收敛：d_k 大时点积过大、softmax 饱和；fp16 下还可能直接溢出。

📐 推导 ViT 完整流程（从图像到分类结果）
Step 1 · Patch Embedding

输入图像 $x\in\mathbb{R}^{H\times W\times C}$（如 $224\times224\times3$），切成 $P\times P$ 的 patch：

$$N = \frac{H}{P}\times\frac{W}{P} = \frac{224}{16}\times\frac{224}{16} = 196$$

每个 patch 展平为 $P^2C = 16{\times}16{\times}3 = 768$ 维，再线性投影到 $d_{\text{model}}$：$\ \texttt{patch\_embed}=\mathrm{Linear}(P^2C,\ d_{\text{model}})$。

Step 2 · 加 [CLS] 与位置编码

序列前面加可学习的 $[\mathrm{CLS}]$，长度变 $196+1=197$，再加可学习位置编码：

$$z_0 = [\,x_{\text{cls}};\ p_1 E;\ \dots;\ p_N E\,] + E_{\text{pos}},\qquad E_{\text{pos}}\in\mathbb{R}^{(N+1)\times d}$$
Step 3 · Transformer Encoder（×L）

每层：$\mathrm{LN}\to$ Multi-Head Self-Attention $\to$ 残差 $\to \mathrm{LN}\to$ FFN $\to$ 残差。注意是双向注意力（非 GPT 的因果），每个 patch 能看到所有 patch。

Step 4 · 分类头
$$y = \mathrm{MLP}\big(\mathrm{LN}(z_L[0])\big)$$

取 $[\mathrm{CLS}]$ 的最终表示过 MLP Head 得类别概率。参数量（ViT-Base，$d=768,\ L=12,\ h=12$）$\approx 86\mathrm{M}$（比 ResNet-50 的 $25\mathrm{M}$ 更大）。

🔥 ViT 的关键洞察

CNN vs ViT 的本质差异：CNN 通过卷积核天然具有局部感受野和平移不变性；ViT 没有这些归纳偏置（inductive bias），完全靠数据学习。所以 ViT 在小数据集上不如 CNN，但在大数据集上远超 CNN。

为什么 ViT 对多模态如此重要：ViT 让图像和文本统一成了相同的表示形式——token 序列。这为后面把图像 token 和文本 token 拼在一起送入 LLM 铺平了道路。

🗣️ 大白话 · ViT 干的事，就是把一张图剪成拼图小块，每块当一个「单词」，再像读句子一样读图。[CLS] token 像个班长：开会时它静静听完所有同学（patch）发言，最后由它代表全班给出结论（分类）。而「没有归纳偏置」的意思是：ViT 是张白纸，不像 CNN 自带「相邻像素相关、平移不变」这些看图常识 —— 所以图给少了它还不如自带常识的 CNN，可一旦图管够，它反而能学到更通透、更全局的关系。

🔬 复现实验 · patch embedding 其实就是一个卷积

ViT 第一步看着玄乎，其实「切 patch + 展平 + 线性投影」严格等价于一个 kernel=stride=P 的卷积。亲手验证两种写法逐元素相等（差 ~1e-6），你就真懂了 patch embedding，不再被唬住。

import torch, torch.nn as nn, torch.nn.functional as F B, C, H, P, D = 1, 3, 224, 16, 768 x = torch.randn(B, C, H, H) # 写法 A：一个卷积（timm / 官方就是这么实现的） conv = nn.Conv2d(C, D, kernel_size=P, stride=P) tok_a = conv(x).flatten(2).transpose(1, 2) # (B, 196, 768) # 写法 B：手动切 patch + 展平 + 线性（复用 conv 的同一套权重） patches = F.unfold(x, kernel_size=P, stride=P) # (B, C*P*P, 196) W = conv.weight.reshape(D, -1) # (768, C*P*P) tok_b = patches.transpose(1, 2) @ W.t() + conv.bias # (B, 196, 768) print("max diff =", (tok_a - tok_b).abs().max().item()) # 预期 ~1e-6 → 两者等价 print("token 序列形状 =", tuple(tok_a.shape)) # (1, 196, 768)
切 patch 不是什么新操作，就是一次卷积。看懂这点，ViT 的「图像 → 序列」就没有黑箱了。

📑 工业实证 · 大厂战报

ViT 不是天生就强 —— 它「数据饥渴」。原论文实测：只在 ImageNet-1k（约 130 万张）上训，ViT 打不过同级 ResNet；放大到 ImageNet-21k（约 1400 万）才追平；只有喂到 Google 内部的 JFT-300M（3 亿张），ViT-L/16 才真正爆发 —— ImageNet top-1 达 88.5%，超过当时最强 CNN，且训练算力还少约 4×。原因正是今天讲的「没有归纳偏置」：先验少，就得用海量数据把先验「喂」出来。

另一条出路是 DeiT：不靠外部大数据，改用强数据增广 + 正则 + 蒸馏，让 ViT 只在 ImageNet-1k 上也能训出有竞争力的精度。这条「配方换数据」的思路，正是明天 P05 的主题。

来源：ViT（arXiv:2010.11929） · DeiT（arXiv:2012.12877）
🐛 调试实录 · failure modes

① 忘了位置编码：ViT 对 patch 顺序无感，没位置编码就等于把拼图打乱还让它认图 → 精度暴跌。

② 从零训 ViT 在小数据上严重过拟合：归纳偏置少 → 必须上强增广（RandAug、Mixup）和正则，或干脆用预训练权重。

③ 换了输入分辨率就报错 / 掉点：位置编码长度对不上 → 需对 pos-embed 做插值（interpolate_pos_encoding）。

④ 预训练 ViT 精度异常低：预处理没对齐 —— 必须用该权重配套的 resize / 均值方差（和 D11 的 preprocess 同理）。

D01 Encoder vs Decoder：从 ViT 到 GPT 的思维转变 ▶
📊 三种架构 = 三种注意力可见性

学习目标

理解 Encoder-only（BERT / ViT）、Decoder-only（GPT）、Encoder-Decoder（T5）三种架构的本质差异，搞清楚为什么现在主流 LLM 都选择 decoder-only。这是从你熟悉的 ViT 转向 GPT 的第一个思维转变。

🔥 核心概念

Causal Attention（因果注意力）是 decoder-only 和你熟悉的 ViT 最根本的区别。ViT 中每个 patch token 可以看到所有其他 token（双向注意力），GPT 中每个 token 只能看到它之前的 token（单向），通过 causal mask 实现。

理解这一点就理解了「自回归生成」——模型一个 token 一个 token 地预测下一个词。

📐 推导 Causal Attention 与标准 Self-Attention 的区别

标准 Self-Attention（你在 ViT 里熟悉的）：

$$\mathrm{Attention}(Q,K,V) = \mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$

Causal Self-Attention（GPT 使用）：在分数上加一个上三角 mask $M$：

$$\mathrm{Attention}(Q,K,V) = \mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}} + M\right)V, \qquad M_{ij} = \begin{cases}0 & i\ge j\\[2pt] -\infty & i效果：位置 $i$ 的 token 只能 attend 到 $[0,1,\dots,i]$，看不到未来的 $[i{+}1,i{+}2,\dots]$ 位置。

D02 Tokenization：BPE、SentencePiece 与词表设计 ▶
📊 文本 → token id：语言模型的「入口」

学习目标

理解文本如何变成 token ID 序列。这是 CV 人最容易忽略的部分——图像天然是连续的，但语言模型的输入是离散的整数序列。这也直接关系到中文效率和多模态里「视觉 token vs 文本 token」的统一（D13）。

🔥 核心概念

BPE（Byte Pair Encoding）是目前主流的 tokenizer 算法。核心思路：从字符级开始，不断合并出现频率最高的 pair，直到词表达到预设大小。

词表大小直接影响：嵌入层参数量、序列长度（词表越大同一段文本 token 越少）、多语言能力。

📐 推导 BPE 算法完整步骤（需要手动走一遍）

初始词表：所有单个字符 {'l','o','w','e','r','n','s','t',…}。语料统计：low×5、lower×2、newest×6 …

迭代过程

① 统计所有相邻 pair 频率 → ('e','s') 出现 9 次（最高）→ 合并为 'es'
② 更新语料、重新统计 → ('es','t') 9 次 → 合并为 'est'
③ 继续，直到词表大小 = 目标值（如 $32000$）

现代变体

Byte-level BPE（GPT-2/3/4）：以 byte 而非 unicode 字符为起点。
SentencePiece（Llama/Qwen）：直接在原始文本上训练，无需预分词。

D03 GPT 完整架构：从 Embedding 到输出概率 ▶
📊 GPT 前向：从 token id 到下一个词的概率

学习目标

完整理解 GPT 系列的前向传播过程：token embedding + positional encoding → N 层 decoder block → lm_head → 概率分布。这是后面所有 LLM / MLLM 的语言骨架。

🔥 GPT Decoder Block

结构（每层重复 N 次）：x → LayerNorm → Causal Multi-Head Self-Attention → 残差连接 → LayerNorm → FFN（MLP）→ 残差连接 → output

和 ViT Block 的区别：(1) attention 有 causal mask；(2) 没有 cross-attention（纯 decoder）；(3) 通常用 Pre-Norm（ViT 也是）。

📐 推导 完整前向过程与参数量估算（面试常考）

完整前向过程（对照 nanoGPT 代码理解）：

① Token Embedding
$$E \in \mathbb{R}^{V\times d},\qquad h_0 = E[x] + \mathrm{PE}\ \ (\text{PE 为位置编码})$$
② Transformer Layers（×N，Pre-Norm）
$$\begin{aligned} h'_l &= h_l + \mathrm{CausalMHA}\big(\mathrm{LN}(h_l)\big)\\ h_{l+1} &= h'_l + \mathrm{FFN}\big(\mathrm{LN}(h'_l)\big) \end{aligned}$$

其中 $\mathrm{FFN}(x)=W_2\,\mathrm{GELU}(W_1 x)$；现代模型（Llama）用 SwiGLU：$\mathrm{FFN}(x)=W_2\big(\mathrm{SiLU}(W_1 x)\odot W_3 x\big)$。

③ 输出层（权重共享）
$$\text{logits} = \mathrm{LN}(h_N)\,E^\top,\qquad P(\text{next}) = \mathrm{softmax}(\text{logits})$$
参数量估算（面试常考）

Embedding $V\times d$；每层 Attention $4d^2$（Q/K/V/O）、FFN $\approx 8d^2$，故

$$\text{总参数} \approx 12\,N d^2.\qquad \text{7B: } N{=}32,\ d{=}4096 \Rightarrow 12\times32\times4096^2 \approx 6.4\mathrm{B}$$

动手：一个 GPT Decoder Block

import torch, torch.nn as nn class Block(nn.Module): # Pre-Norm 风格（GPT-2/Llama 都是） def __init__(self, d, h): super().__init__() self.ln1, self.ln2 = nn.LayerNorm(d), nn.LayerNorm(d) self.attn = nn.MultiheadAttention(d, h, batch_first=True) self.ffn = nn.Sequential(nn.Linear(d, 4*d), nn.GELU(), nn.Linear(4*d, d)) def forward(self, x, causal_mask): a, _ = self.attn(self.ln1(x), self.ln1(x), self.ln1(x), attn_mask=causal_mask, need_weights=False) x = x + a # 残差① x = x + self.ffn(self.ln2(x)) # 残差②（残差思想来自 P02 ResNet） return x d, h, n = 768, 12, 16 blk = Block(d, h) mask = torch.triu(torch.full((n, n), float("-inf")), diagonal=1) # causal print(blk(torch.randn(1, n, d), mask).shape) # [1, 16, 768] # 把 N 个 Block 叠起来 + embedding + lm_head 就是一个完整 GPT（对照 nanoGPT model.py）

D04 位置编码：从 Sinusoidal 到 RoPE ▶
📊 位置编码三代演进（RoPE 是当下标准）

学习目标

Transformer 本身对位置不敏感（permutation invariant），必须注入位置信息。理解三代位置编码的演进——尤其 RoPE，它是后面所有现代模型（含 D17 的 M-RoPE）的基础。

📐 推导 三代位置编码对比（RoPE 重点理解）
第一代 · Sinusoidal（原始 Transformer / ViT）
$$\mathrm{PE}(pos,2i) = \sin\!\Big(\frac{pos}{10000^{2i/d}}\Big),\qquad \mathrm{PE}(pos,2i{+}1) = \cos\!\Big(\frac{pos}{10000^{2i/d}}\Big)$$

加到 embedding 上 $h_0 = E[x]+\mathrm{PE}$。问题：绝对位置，难外推到训练长度之外。

第二代 · ALiBi（BLOOM）

不加到 embedding，而是加到注意力分数上（$m$ 为每个 head 不同的斜率）：

$$\mathrm{Attention}_{ij} \mathrel{+}= -\,m\,|i-j|$$

简单但有效，天然支持外推。

第三代 · RoPE（Llama / Qwen / 多数现代模型）

核心：用旋转矩阵编码相对位置，对 $q,k$ 的每对维度做旋转：

$$\begin{pmatrix} q'_{2i}\\ q'_{2i+1}\end{pmatrix} = \begin{pmatrix}\cos m\theta_i & -\sin m\theta_i\\ \sin m\theta_i & \cos m\theta_i\end{pmatrix} \begin{pmatrix} q_{2i}\\ q_{2i+1}\end{pmatrix},\qquad \theta_i = 10000^{-2i/d}$$

于是 $q_m\cdot k_n$ 的内积只依赖 $m-n$（相对距离）—— 这就是「旋转位置编码」名字的由来。

🔥 为什么 RoPE 成为标准

它优雅地实现了：(1) 注意力分数只依赖相对位置；(2) 通过 NTK-aware scaling 可以外推到更长序列；(3) 计算开销极小。你后面看的所有模型（Llama、Qwen、InternVL）都用 RoPE。

动手：RoPE 旋转实现

import torch def rope(x, theta=10000.0): # x: (B, T, d)，d 为偶数；对每对维度按位置旋转 B, T, d = x.shape pos = torch.arange(T).float() freqs = theta ** (-torch.arange(0, d, 2).float() / d) # θ_i = 10000^(-2i/d) ang = pos[:, None] * freqs[None, :] # (T, d/2) 旋转角 = 位置×θ cos, sin = ang.cos(), ang.sin() x1, x2 = x[..., 0::2], x[..., 1::2] # 成对取维度 out = torch.empty_like(x) out[..., 0::2] = x1 * cos - x2 * sin # 旋转矩阵作用 out[..., 1::2] = x1 * sin + x2 * cos return out q = torch.randn(1, 8, 64) print(rope(q).shape) # [1, 8, 64] # 对 q、k 各做一次 rope 再算注意力 → 分数自动只依赖相对位置（见推导）

📐 推导 预训练损失与 Perplexity
预训练损失（自回归交叉熵）

给定序列 $x=(x_1,x_2,\dots,x_T)$：

$$L = -\sum_{i} \log P(x_i \mid x_1,\dots,x_{i-1};\,\theta)$$

就是标准交叉熵 —— 和你做分类的 CE loss 一模一样，只是「类别数」= 词表大小 $V$（通常 32K–150K）。

Perplexity（困惑度）
$$\mathrm{PPL} = \exp\!\big(L/T\big)\quad(T\text{ 为序列长度})$$

PPL 越低越好，直觉上代表「平均每个位置模型犹豫的选项数」。

🔥 采样策略（面试高频）

Greedy：每步选概率最大的 token。确定性但无聊。
Temperature：logits / T 后再 softmax。T<1 更确定，T>1 更随机。
Top-k：只保留概率最高的 k 个 token，其余置 0 后重新归一化。
Top-p（Nucleus）：保留累积概率达到 p 的最小 token 集合。自适应，比 top-k 更灵活。
Repetition Penalty：降低已出现 token 的概率，减少重复。

📊 LLM 三阶段：续写 → 听指令 → 对齐偏好

学习目标

理解为什么不能只做预训练——预训练只学会「续写」，需要 SFT 学会「听指令」，需要 RLHF 学会「对齐人类偏好」。这三阶段是后面 LLaVA 多模态训练(D14/D20)的母版。

🔥 三阶段对比

① 预训练（Pre-training）：海量无标注文本（万亿 token），next token prediction，学到语言知识和世界知识。需要数千张 GPU。你不会从零做这一步。

② 监督微调（SFT）：高质量 instruction-response 对（数万到数十万条），让模型学会按指令格式回答。loss 通常只算 response 部分。

③ RLHF / DPO：人类对同一问题的多个回答做偏好排序，训练 reward model 或直接用 DPO 优化。让输出更安全、更有帮助。

🗣️ 大白话 · 把训练 LLM 想成培养一个新员工：① 预训练 = 让他把全世界的书报读一遍 —— 博学，但不一定会干你这行的活；② SFT = 老师傅手把手教「遇到这类问题就该这么答」，学会按规矩做事；③ RLHF / DPO = 老板反复反馈「这么说我更满意」，让他学会察言观色、对齐你的口味。只读过书（只预训练）的人，你问他事，他往往只顺着你的话续写半篇作文，而不是好好回答你 —— 这就是为什么必须有 ②③。

📑 工业实证 · 大厂战报

现象：「先 SFT 后 RL，奖励会先变差、再变好」（Reward Hockey-Stick 曲线）。很多团队在 SFT / 蒸馏之后接 RL，会发现头几十~几百步奖励不升反降、benchmark 掉点，探到一个谷底后才回升、并最终反超起点 —— 形状像一根曲棍球杆。新手常在谷底误判「RL 训崩了」而提前停手，其实是停早了。

为什么会这样：SFT 把策略压得过于确定（熵很低），RL 早期一探索就偏离 SFT 分布，加上 reward model 给这些 out-of-distribution 输出打分不准 → 短暂塌陷。怎么稳住：① 用足够的 KL penalty 把策略拴在参考模型附近；② 别把 SFT 练到熵太低；③ 谷底要敢熬过去 —— 同时盯 KL、熵、回答长度，而不是只盯单一 reward。

DeepSeek-R1 的佐证：纯 RL 的 R1-Zero 会出现可读性差、中英混杂、重复，所以 R1 才先用冷启动 SFT 数据稳住格式再上 RL；而他们加的「语言一致性奖励」反而让某些 benchmark 掉分 —— 一个为可读性牺牲少量分数的真实取舍。RL 过程中回答长度持续变长，并自发涌现「反思 / aha moment」。

来源：DeepSeek-R1（arXiv:2501.12948） · Balanced Actor Initialization：蒸馏模型 RLHF 的 hockey-stick 与稳定化（arXiv:2509.00309）

🗣️ 大白话 · 这根「先变差再变好」的曲线，就像让一个打球姿势已经定型的老球员改用更标准的新动作：刚改那几天浑身别扭、打得反而更烂（谷底）；可一旦熬过适应期、新动作练顺，水平会反超从前。很多人就栽在「改了反而变差」的头几天放弃了 —— 其实再咬牙几天就柳暗花明。

📐 推导 SFT 的 loss 与预训练的区别

预训练 loss：对整个序列 $[x_1,x_2,\dots,x_T]$ 都算 loss。
SFT loss：只对 response（assistant）部分算 loss。

ChatML 格式（Qwen 使用）
<|im_start|>system 你是一个助手<|im_end|> <|im_start|>user 什么是超分辨率？<|im_end|> <|im_start|>assistant 超分辨率是…<|im_end|>

D07DPO：不需要 Reward Model 的对齐方法▶
📊 RLHF vs DPO：DPO 消掉了 Reward Model

学习目标

RLHF 太复杂（需要训练 reward model + PPO），DPO 把它简化成了一个简单的分类式损失。现在大多数开源模型都用 DPO 或其变体。

📐 推导 DPO 损失函数完整推导
RLHF 目标（Bradley-Terry 模型）
$$P(y_w \succ y_l \mid x) = \sigma\big(r(x,y_w) - r(x,y_l)\big)$$

$y_w$ 是人类偏好的回答、$y_l$ 是被拒绝的。RLHF 需先训 reward model $r(x,y)$，再用 PPO 优化策略。

DPO 的关键洞察

最优策略 $\pi^{*}$ 与 reward 有解析关系：

$$r(x,y) = \beta \log\frac{\pi^{*}(y\mid x)}{\pi_{\text{ref}}(y\mid x)} + \text{const}$$

代入 Bradley-Terry，reward model 被消掉，直接得到 DPO loss：

$$L_{\text{DPO}} = -\,\mathbb{E}\left[\log\sigma\!\left( \beta\log\frac{\pi_\theta(y_w\mid x)}{\pi_{\text{ref}}(y_w\mid x)} - \beta\log\frac{\pi_\theta(y_l\mid x)}{\pi_{\text{ref}}(y_l\mid x)}\right)\right]$$

直觉：抬高好回答概率、压低差回答概率，同时由 $\beta$ 控制不偏离参考模型 $\pi_{\text{ref}}$ 太远。

动手：DPO loss 就这几行

import torch.nn.functional as F def dpo_loss(logp_w, logp_l, ref_w, ref_l, beta=0.1): # logp_*: 当前策略 π_θ 对 chosen(w)/rejected(l) 的序列 log 概率 # ref_* : 参考模型 π_ref（通常是 SFT 后冻结的模型）的对应 log 概率 pi_logratio = logp_w - logp_l # 策略：更偏好 w 多少 ref_logratio = ref_w - ref_l # 参考：原本偏好 w 多少 logits = beta * (pi_logratio - ref_logratio) return -F.logsigmoid(logits).mean() # 让"比参考更偏好 w"，但 β 控制别跑太远 # 直觉：抬高好回答概率、压低差回答概率，同时用 β 约束不偏离 SFT 模型太多 # 对比 RLHF：这里没有 reward model、没有 PPO，只有一个交叉熵式的 loss

D08LoRA：低秩适配的原理与实现▶
📊 LoRA：冻结大矩阵，只训低秩旁路

学习目标

LoRA 是你后面做任何微调实验（D09 本地微调、D20 训 MLLM）的基础工具，必须吃透——它是你在有限显存上能动手的前提。

📐 推导 LoRA 核心数学（务必理解）

全量微调 $W' = W + \Delta W$，其中 $\Delta W\in\mathbb{R}^{d\times d}$（参数量巨大）。LoRA 假设 $\Delta W$ 低秩，分解为：

$$\Delta W = B A,\qquad A\in\mathbb{R}^{r\times d},\ B\in\mathbb{R}^{d\times r},\ r\ll d\ (\text{rank, 常 8–64})$$

前向：$h = (W+\Delta W)x = Wx + BAx$。

参数量对比（$d=4096,\ r=16$）
$$\underbrace{4096\times4096 = 16.7\mathrm{M}}_{\text{全量 }\Delta W} \quad\gg\quad \underbrace{4096{\times}16 + 16{\times}4096 = 131\mathrm{K}}_{\text{LoRA }A+B} \quad(\text{压缩 }128\times)$$
初始化

$A\sim\mathcal{N}(0,\sigma^2)$（随机），$B=0$（零初始化，保证起步 $\Delta W=0$）；缩放因子 $\alpha/r$（$\alpha$ 常取 $r$ 的 1–2 倍）。

🔥 QLoRA

QLoRA = 量化基础模型 + LoRA。基础模型以 4-bit NF4 格式加载（省内存），只训练 LoRA 的 A/B 矩阵（FP16/BF16）。这就是你在 32GB MacBook 上能微调 7B 模型的原因。

动手：30 行实现一个 LoRA 层

import torch, torch.nn as nn class LoRALinear(nn.Module): def __init__(self, base: nn.Linear, r=16, alpha=32): super().__init__() self.base = base # 原权重 W for p in self.base.parameters(): p.requires_grad = False # ❄️ 冻结 W d_in, d_out = base.in_features, base.out_features self.A = nn.Parameter(torch.randn(r, d_in) * 0.01) # 随机初始化 self.B = nn.Parameter(torch.zeros(d_out, r)) # 零初始化 → 起步 ΔW=0 self.scale = alpha / r # 缩放因子 def forward(self, x): return self.base(x) + self.scale * (x @ self.A.T) @ self.B.T # Wx + BAx lin = nn.Linear(4096, 4096) lora = LoRALinear(lin, r=16) trainable = sum(p.numel() for p in lora.parameters() if p.requires_grad) print(f"可训练参数: {trainable/1e3:.0f}K（全量是 {4096*4096/1e6:.1f}M）") # 实战直接用 peft: get_peft_model(model, LoraConfig(r=16, ...))

D10MoE 架构与 KV Cache 推理优化▶
📊 MoE（稀疏激活）+ KV Cache（加速生成）

学习目标

理解两个在现代 LLM 中无处不在的工程概念：Mixture of Experts（稀疏激活，连 D16 InternVL/DeepSeek-V3）和 KV Cache（加速推理，连 D15 视觉 token 只编码一次）。

📐 推导 MoE 与 KV Cache 原理
Mixture of Experts（MoE）

标准 FFN：每个 token 都过同一个 $y=\mathrm{FFN}(x)$。MoE 则路由到少数专家：

$$\mathrm{gate}(x) = \mathrm{softmax}(W_g x),\qquad y = \sum_{i\in\text{top-}k} \mathrm{gate}_i(x)\cdot \mathrm{FFN}_i(x)$$

只计算被选中的 top-$k$ 个专家（通常 $k=2$）。例：Mixtral 8×7B 共 8 专家、每次激活 2 个 —— 总参 $46.7\mathrm{B}$，但每 token 只用 $\sim13\mathrm{B}$，推理快、效果好。

KV Cache

自回归生成第 $t$ 步需 $\mathrm{Attention}\big(q_t,\,[k_1,\dots,k_t],\,[v_1,\dots,v_t]\big)$。注意 $k_1\dots k_{t-1},\,v_1\dots v_{t-1}$ 之前已算过 → 缓存复用，每步只需：

① 算新 token 的 $q_t,k_t,v_t$ → ② 把 $k_t,v_t$ 追加缓存 → ③ $q_t$ attend 整个缓存。

$$\text{显存} \approx 2\times n_{\text{layers}}\times d_{\text{model}}\times \text{seq\_len}\times \text{dtype}\quad(\text{7B / 4K ctx}\approx 1\mathrm{GB})$$

动手：KV Cache 的本质（伪代码）

# 自回归生成时，历史的 K、V 不会变 → 缓存起来，每步只算新 token cache_k, cache_v = [], [] def step(q_t, k_t, v_t): cache_k.append(k_t); cache_v.append(v_t) # 追加新 token 的 K、V K = torch.cat(cache_k, dim=1) # 复用全部历史 V = torch.cat(cache_v, dim=1) return attention(q_t, K, V) # 只对新 q_t 算注意力 # 不缓存：每步重算 1..t 的 K、V → O(t²) # 缓存后：每步只算第 t 个 → O(t)，长文本生成提速巨大 # 代价：显存 ≈ 2·layers·d·seq·dtype（7B/4K ≈ 1GB）→ 用 GQA/MQA 省 # 注：HF 里 model.generate(use_cache=True) 默认就开了

一、动机：怎么让图像和文本「可比较」

图像和文本是两种完全不同的模态，无法直接比较。CLIP 的思路极其干净：用两个编码器各自把图像、文本映射到同一个 d 维向量空间，在这个空间里，「一张猫的图」和「a cat」这句话的向量应该挨得很近。一旦图文进入同一空间，「图像理解」就被转化成了「向量检索」。

🔥 CLIP 三件套

① 图像编码器（ViT-L/14 或 ViT-bigG）：图像 → 一个全局图像向量 v。

② 文本编码器（Transformer）：文本 → 一个全局文本向量 u。

③ 对比学习：在一个 batch 的 N 对图文上，构造 N×N 相似度矩阵，拉近对角线（匹配对）、推远其余（负样本）。两个向量都做 L2 归一化，相似度就是余弦相似度。

对多模态大模型而言，CLIP 真正值钱的是「图像编码器」——它产出的视觉特征天然和语言对齐，后面 LLaVA 只需一个小 projector 就能接上 LLM。

🗣️ 大白话 · CLIP 训练像一场超大型相亲配对：一屋子 N 张图配 N 句话，每对本是天生一对。模型反复练习 —— 把「我的那一位」拉到身边，把其他所有人都往外推。练到最后眼力毒到：随便给一张新图，它能在一堆文字里一眼挑出最配的那句。这「一眼认人」的本事就是 zero-shot 分类 —— 把每个候选类别写成一句话，看图跟哪句最配。

💡 和你的 CV 直觉对接

这其实就是你熟悉的度量学习 / 表征对齐：把 triplet loss 里「锚-正-负」的思路,扩展成「用整个 batch 内所有不匹配对当负样本」。CLIP 没有发明新数学,它的赢点是4 亿图文对 + 超大 batch——数据和规模再次胜过技巧。

📑 工业实证 · 大厂战报

「数据 > 损失函数」不是口号，是有数字的。OpenCLIP 团队把对比预训练做成可复现的幂律 scaling：性能随算力 / 数据 / 模型规模平滑提升；但同样算力下，scaling 的斜率取决于数据分布 —— 不同来源的数据，效率差很多。

更狠的反例来自 DataComp：固定模型与算力、只改「怎么筛数据」，用筛出来的 DataComp-1B 训出的 ViT-L/14 在 ImageNet 零样本拿到 79.2%，反超相同算力的 OpenAI 原版 75.5%；甚至比 LAION-2B 上训的、更大的 ViT-g 还强，且省 9× 算力。结论：决定 CLIP 上限的是数据的规模与质量，而非损失函数上的小技巧 —— 这也是为什么后面所有 MLLM 抢的都是「更干净的视觉塔 + 更好的图文数据」。

二、对比损失（InfoNCE）

📐 推导 CLIP 对比学习损失 InfoNCE（务必能默写）

一个 batch 含 $N$ 对 (image, text)。两个编码器各自输出并 L2 归一化到单位球：$v_i = f_{\text{img}}(x_i)/\|\cdot\|,\ u_j = f_{\text{txt}}(t_j)/\|\cdot\|$。

相似度矩阵（余弦 × 温度）
$$S_{ij} = \exp(\tau)\cdot(v_i\cdot u_j)\qquad(\tau\text{ 可学习，等价于 }1/\text{temperature})$$
对称交叉熵损失
$$L_{i2t} = -\frac{1}{N}\sum_i \log\frac{\exp(S_{ii})}{\sum_j \exp(S_{ij})} \quad(\text{按行}),\qquad L_{t2i} = -\frac{1}{N}\sum_j \log\frac{\exp(S_{jj})}{\sum_i \exp(S_{ij})}\quad(\text{按列})$$ $$L = \tfrac{1}{2}\big(L_{i2t} + L_{t2i}\big)$$

温度 $\tau$：越大分布越尖锐、越强调最难负样本（但易不稳）；CLIP 设为可学习并裁剪上限防爆炸。
为何大 batch：分母是「该样本 vs batch 内所有负样本」，$N$ 越大负样本越多、对比信号越强 —— CLIP 原论文 batch size $=32768$！

梯度：为什么一行 cross_entropy 就够了
$$\frac{\partial L_{i2t}}{\partial S_{ij}} = \underbrace{\frac{\exp(S_{ij})}{\sum_k \exp(S_{ik})}}_{p_{ij}} \;-\; \mathbb{1}[i=j]$$

$p_{ij}$ 是第 $i$ 行的 softmax。这和交叉熵一模一样：把对角线 logit 推高、其余推低 —— 所以代码里一行 F.cross_entropy(logits, labels) 就够了，labels = torch.arange(N)（对角线才是匹配对）。

温度的裁剪（工程必做，不做会 NaN）
$$\text{logit\_scale} = \exp(t),\qquad t \le \ln 100 \;\Longleftrightarrow\; \text{temperature} = \tfrac{1}{\text{logit\_scale}} \ge 0.01$$

不裁剪，$t$ 会被优化器一路推高 → logits 爆炸 → softmax 出 NaN。代码：logit_scale.data.clamp_(max=math.log(100))（CLIP 官方同款）。

为什么大 batch 真有用：InfoNCE 是互信息下界
$$\mathbb{E}[L] \;\ge\; \log N - I(\text{image};\text{text})$$

最小化 InfoNCE 等价于最大化图文互信息 $I$ 的一个下界；$N$ 越大下界越紧 → 表征越好。这就是 CLIP 堆到 batch $=32768$ 的理论依据，也是「规模 > 技巧」的根。

🗣️ 大白话 · 几个旋钮翻成人话 —— 温度像自信心：调高 = 模型很轴，只认最像的那个；调低 = 佛系，觉得谁都有点像。大 batch像相亲现场人多：干扰项越多越能逼出「火眼金睛」，一对一相亲太容易、练不出本事。L2 归一化像比身材只看比例、不看绝对胖瘦：先把每个向量缩到一样长，比的是「方向像不像」，而不是「谁向量模长大谁就赢」。

三、动手：用 CLIP 做 zero-shot 分类

四、从零写对比损失 + MiniCLIP（今天的 capstone 产物）

调一次 API 不等于懂。下面把 CLIP 的核心 —— 对称 InfoNCE —— 亲手写出来，再拼一个能训练的 MiniCLIP。这两段就是 vision/clip.py，后面整条多模态主线都复用它。

# nano-mllm/vision/clip.py —— 今天的 capstone 产物：对比损失 + 可训练 MiniCLIP import math, timm, torch, torch.nn as nn, torch.nn.functional as F def clip_contrastive_loss(img_emb, txt_emb, logit_scale): """img_emb,txt_emb:(N,d)；logit_scale 是可学习标量。返回对称 InfoNCE。""" img = F.normalize(img_emb, dim=-1) # L2 归一化到单位球（漏了它 loss 不降！） txt = F.normalize(txt_emb, dim=-1) logits = logit_scale.exp() * img @ txt.t() # (N,N) 相似度矩阵 S_ij labels = torch.arange(img.size(0), device=img.device) # 对角线才是匹配对 loss_i2t = F.cross_entropy(logits, labels) # 按行：每张图找它的文 loss_t2i = F.cross_entropy(logits.t(), labels) # 按列：每段文找它的图 return (loss_i2t + loss_t2i) / 2, logits class MiniCLIP(nn.Module): def __init__(self, vocab=49408, d=256, ctx=32): super().__init__() self.visual = timm.create_model("vit_small_patch16_224", num_classes=0, pretrained=True) # 图像塔 self.img_proj = nn.Linear(self.visual.num_features, d) self.token_emb = nn.Embedding(vocab, d) # 文本塔（极简） self.pos_emb = nn.Parameter(torch.zeros(ctx, d)) layer = nn.TransformerEncoderLayer(d, 8, batch_first=True) self.text = nn.TransformerEncoder(layer, 3) self.txt_proj = nn.Linear(d, d) self.logit_scale = nn.Parameter(torch.tensor(2.6593)) # ln(1/0.07)，CLIP 初值 def encode_image(self, x): return self.img_proj(self.visual(x)) def encode_text(self, ids): h = self.token_emb(ids) + self.pos_emb[:ids.size(1)] return self.txt_proj(self.text(h)[:, -1]) # 取末 token 当句向量 def forward(self, img, ids): return self.encode_image(img), self.encode_text(ids)

写完先别急着上大数据。对比学习第一件事永远是「单 batch 过拟合自检」：连一个 batch 都学不到对角线 100%，代码一定有 bug，上再多数据也是白烧显卡。

# 单 batch 过拟合自检：你的对比损失能把对角线学到 100% 吗？（CPU 上约 1 分钟） torch.manual_seed(0) model = MiniCLIP(); opt = torch.optim.AdamW(model.parameters(), lr=1e-4) img = torch.randn(8, 3, 224, 224) # 假装 8 张图 ids = torch.randint(0, 49408, (8, 16)) # 假装 8 段配对文本（第 i 段配第 i 张） for step in range(301): i_emb, t_emb = model(img, ids) loss, logits = clip_contrastive_loss(i_emb, t_emb, model.logit_scale) opt.zero_grad(); loss.backward() model.logit_scale.data.clamp_(max=math.log(100)) # ln100：防温度爆炸（CLIP 同款） opt.step() if step % 100 == 0: acc = (logits.argmax(-1) == torch.arange(8)).float().mean().item() print(f"step {step:3d} loss {loss.item():.3f} in-batch acc {acc:.2f}") # 预期：loss 从 ~2.08(=ln8) 一路降到 <0.05，in-batch acc → 1.00 # 没降？看下面「🐛 调试实录」第 ①③ 条 —— 十有八九是归一化或配对错位

# nano-mllm/eval/zeroshot_cifar10.py —— 复现 CLIP 论文的零样本分类 import open_clip, torch from torchvision.datasets import CIFAR10 from torch.utils.data import DataLoader model, _, preprocess = open_clip.create_model_and_transforms("ViT-B-32", pretrained="openai") tokenizer = open_clip.get_tokenizer("ViT-B-32") model.eval().requires_grad_(False) classes = ["airplane","automobile","bird","cat","deer","dog","frog","horse","ship","truck"] templates = ["a photo of a {}.", "a blurry photo of a {}.", "a photo of the {}."] # 提示词集成 with torch.no_grad(): # 文本权重：每类多模板取平均 cols = [] for c in classes: e = model.encode_text(tokenizer([t.format(c) for t in templates])) e = e / e.norm(dim=-1, keepdim=True) cols.append(e.mean(0)) text_w = torch.stack(cols, dim=1) text_w = text_w / text_w.norm(dim=0, keepdim=True) # (d,10) ds = CIFAR10("./data", train=False, download=True, transform=preprocess) hit = tot = 0 for img, y in DataLoader(ds, batch_size=256): with torch.no_grad(): f = model.encode_image(img); f = f / f.norm(dim=-1, keepdim=True) pred = (f @ text_w).argmax(-1) hit += (pred == y).sum().item(); tot += img.size(0) print(f"CIFAR-10 zero-shot top-1 = {100*hit/tot:.2f}%")

📊 SigLIP vs CLIP：归一化方式之别

学习目标

CLIP 用 softmax 对比,分母要看「整个 batch」,于是必须超大 batch + 跨卡同步,很贵。SigLIP 把它换成逐对 sigmoid,一举解决。学完今天你应能：(1) 说清 softmax 对比「贵在哪」;(2) 默写 SigLIP 的 sigmoid loss、解释 bias 项;(3) 说清「为什么 sigmoid 省掉了跨卡同步」;(4) 知道主流 MLLM 各用什么视觉编码器、怎么选;(5) 用 HF 跑一次 SigLIP(记住推理用 sigmoid 不是 softmax)。

一、动机：CLIP softmax 贵在哪

CLIP 的损失分母是 ∑_j exp(S_ij)——要对「这张图 vs batch 里所有文本」做归一化。batch 越大效果越好,但 batch 大到几万时,负样本分散在几十张卡上,每步都要 all-gather 把所有特征拉到一起算 softmax,通信开销巨大。SigLIP 的洞察:把「N 选 1 的多分类」换成「N² 个独立的是/否二分类」,每个格子只看自己,归一化消失,跨卡同步也就没了。

🔥 SigLIP 的核心改动

双塔结构和 CLIP 完全一样(图像编码器 + 文本编码器 + 相似度矩阵),唯一变的是 loss：对相似度矩阵的每一个格子独立做 sigmoid 二分类——对角线 label=+1(是匹配对),其余 label=−1(不是)。没有 softmax,所以不需要看到「整行/整列」,各卡算各自的局部矩阵即可。

💡 一句话直觉

CLIP 问的是「在这一排里哪一个是对的?」(必须看全排);SigLIP 问的是「这一对是不是对的?」(只看这一对)。把排他的多分类拆成独立的二分类,通信成本就从 O(全 batch) 降到 O(本地)。

二、SigLIP 损失

📐 推导 Sigmoid 对比损失（对比 CLIP 的 softmax）

归一化向量 $x_i$（图像）、$y_j$（文本），相似度 $s_{ij}=x_i\cdot y_j$；标签 $z_{ij}=+1$（$i=j$ 匹配对）/ $-1$（$i\ne j$ 负样本）。

SigLIP loss（每格独立的 logistic 二分类）
$$L = -\frac{1}{N}\sum_i\sum_j \log\sigma\big(z_{ij}\,(t\cdot s_{ij} + b)\big) \qquad(\sigma=\text{sigmoid},\ t=\text{温度},\ b=\text{可学习 bias})$$

为何需要 bias $b$：负样本（$N^2-N$ 个）远多于正样本（$N$ 个），初期模型会把所有对都判「负」；$b$ 给初始偏置缓解极端不平衡，训练更稳。

对比 CLIP（softmax）
$$\underbrace{L_i = -\log\frac{\exp(s_{ii})}{\sum_j \exp(s_{ij})}}_{\text{CLIP: 分母含整行 → 需全 batch}} \qquad vs \qquad \underbrace{\text{每个 }(i,j)\text{ 独立}}_{\text{SigLIP: 分母消失 → 各卡只算本地块}}$$

收益：① 省跨卡 all-gather、通信大降；② 小 batch 也训得好；③ 效果与 CLIP 持平甚至更好。

🔥 主流 MLLM 的视觉编码器怎么选

LLaVA-1.5：CLIP ViT-L/14 (336px) · Qwen-VL：ViT-bigG (OpenCLIP) · InternVL：InternViT-6B(自训练超大 ViT) · PaliGemma / 新一代：SigLIP ViT-So400m。
选择逻辑:要分辨率高(看清小字/细节) → 336/448px;要训练省 → SigLIP;要视觉能力天花板 → 自训大 ViT(InternViT)。趋势:SigLIP 正在取代 CLIP 成为默认视觉塔。

一、图像怎么变成 token

LLM 只认 token 序列。把图像变 token 的标准流程:切 patch → ViT 编码 → 每个 patch 成一个视觉 token → connector 对齐到 LLM 维度 → 和文本 token 拼成一队。和 D14 的 LLaVA 一脉相承,这里我们把镜头拉近,专门盯住「token 数量」这件要命的事。

🔥 视觉 token 流程四步

① 切 patch + ViT:224px 图 →(224/14)²= 256 token;336px → 576;448px → 1024。

② 动态分辨率:高清图按比例切成多个 tile,每个 tile 各 576~1024 token → 总数 ×tile 数,轻松上千。

③ Connector:把视觉 token 既对齐到 LLM 维度(如 1024→4096),又压缩数量(可选)。

④ 拼接:压缩后的视觉 token 与文本 token 排成一个序列送入 LLM。

💡 和你的超分/图像复原经验对接

「分辨率高看得清,但 token 太多算不动」本质就是你熟悉的 信息量 vs 计算成本 的 trade-off。Pixel Shuffle 把空间分辨率「折叠」进通道维(空间↓、通道↑),正是超分里 sub-pixel convolution 的同款操作——你已经会了。

二、token 数量：算给你看

📐 推导 视觉 token 数量与压缩（工程上最要命的数）
单张图 token 数
$$N = \left(\frac{\text{img\_size}}{\text{patch}}\right)^2:\quad \tfrac{224}{14}{=}16\to256,\quad \tfrac{336}{14}{=}24\to576,\quad \tfrac{448}{14}{=}32\to1024$$
动态分辨率（切 tile，如 InternVL / LLaVA-NeXT）

按长宽比切成 $k$ 个 $448\times448$ tile（再加一张缩略全图）：$N_{\text{total}} = k\times1024\,(+1024)$。例：切 4 tile → $4\times1024 = 4096$ 个 token ⚠ 爆炸。

为何是大问题：视觉与文本 token 抢同一 context；attention 是 $O(L^2)$，序列翻倍 → 计算翻 4 倍 → 推理显著变慢。

四种 Connector / 压缩方案

① MLP（LLaVA）：只对齐维度、不压数量。② Pixel Shuffle：相邻 2×2 token 折叠进通道，数量 $\div4$、维度 $\times4$（几乎不丢信息）。③ Perceiver Resampler（Flamingo）：固定数量 query 做 cross-attention 压到定额。④ Q-Former（BLIP-2）：可学习 query + 多层注意力提取。

口诀：MLP 保真不压 → 数量爆；Resampler / Q-Former 压到固定数 → 可能丢细节；Pixel Shuffle 折叠 → 折中，当前最流行。

def n_visual_tokens(img_size=336, patch=14, tiles=1, shuffle=1): """tiles: 动态分辨率切片数; shuffle: pixel-shuffle 下采样倍数""" per_tile = (img_size // patch) ** 2 return tiles * per_tile // (shuffle ** 2) print(n_visual_tokens(336)) # 576 （LLaVA-1.5） print(n_visual_tokens(448, tiles=4)) # 4096 （动态分辨率，爆炸） print(n_visual_tokens(448, tiles=4, shuffle=2)) # 1024 （Pixel Shuffle 压 1/4） # —— Pixel Shuffle：相邻 2×2 token 折叠进通道（空间↓ 通道↑）—— import torch def pixel_shuffle_down(x, h, w, scale=2): # x: (B, h*w, C) -> (B, h/2 * w/2, C*4) B, _, C = x.shape x = x.view(B, h, w, C) x = x.view(B, h, w // scale, C * scale) # 横向折叠 x = x.permute(0, 2, 1, 3).contiguous() x = x.view(B, w // scale, h // scale, C * scale * scale) return x.permute(0, 2, 1, 3).contiguous().view(B, -1, C * scale * scale) tokens = torch.randn(1, 24 * 24, 1024) # 576 个 1024 维 token out = pixel_shuffle_down(tokens, 24, 24, scale=2) print(out.shape) # (1, 144, 4096) 数量 576→144，维度 1024→4096

一、动机：让「只懂文字」的 LLM「看见」图像

LLM 的输入是一串 token 的词向量（embedding 序列），而图像是连续像素。要让 LLM 处理图像，核心问题只有一个：找一个「翻译官」，把图像变成 LLM 词向量空间里的若干个「伪词」，和文本词向量拼在一起喂进去。LLaVA 给出的答案简单到令人意外——这个翻译官就是一个 MLP。

🔥 LLaVA 三件套

① 视觉编码器（CLIP ViT-L/14，❄️ 冻结）：把图像切成 patch，编码成一串视觉特征 Z_v ∈ ℝ^(576×1024)。用的是 CLIP 倒数第二层的 grid 特征（不是 CLS）。

② Projector / 连接器（🔥 要训练）：一个把 1024 维视觉特征映射到 LLM 词向量维度 4096 的小网络。LLaVA-1 是单层 Linear，LLaVA-1.5 换成 2 层 MLP。它是整个架构里唯一为「对齐」而新增的部件。

③ 大语言模型（Vicuna / Llama）：把这 576 个「视觉词」当外语词，和文本词拼成一个序列，自回归生成回答。

没有 cross-attention，没有 Q-Former。就这么三件套，却在当年打穿了一堆复杂架构——说明瓶颈不在「怎么融合」，而在「数据质量 + LLM 本身够强」。

💡 和你的 CV 直觉对接

ViT 把图像变成 patch token 序列，你已经很熟。LLaVA 做的事，本质就是你做过无数次的「特征空间对齐」——只不过这次是把 CLIP 的视觉特征，用一个线性/MLP 投影对齐到 LLM 的词向量空间。把它类比成「域适配里的一层 projection head」，直觉立刻通了。

二、数据怎么流过模型（维度全程跟踪）

📐 推导 从一张图到一段回答的完整维度变换（务必能默画）

输入：一张 RGB 图像 $X_v \in \mathbb{R}^{336\times336\times3}$。

① 视觉编码（CLIP ViT-L/14, patch=14）

patch 数 $=(336/14)^2 = 24\times24 = 576$；取倒数第二层 grid features（去 $[\mathrm{CLS}]$）：$Z_v = g(X_v)\in\mathbb{R}^{576\times1024}$（$1024$ = CLIP ViT-L 隐藏维）。

② Projector：视觉维 → LLM 词向量维
$$\text{LLaVA-1: } H_v = W Z_v,\ \ W\in\mathbb{R}^{4096\times1024};\qquad \text{LLaVA-1.5: } H_v = W_2\,\mathrm{GELU}(W_1 Z_v)$$

得 $H_v\in\mathbb{R}^{576\times4096}$（$4096$ = Vicuna-7B 隐藏维）—— 576 个「视觉词向量」，与文本词向量同维、可直接拼接。

③ 文本走正常 embedding

"USER: <image>\n描述这张图 ASSISTANT:" → token ids → $H_t\in\mathbb{R}^{L\times4096}$。

④ 拼接成一个序列

把文本里的 <image> 占位符替换成 ② 的 576 个视觉向量：

$$H = [\,H_{\text{pre}};\ H_v(576);\ H_{\text{post}}\,] \in \mathbb{R}^{(L-1+576)\times4096}$$
⑤ LLM 自回归生成
$$p(X_a\mid X_v, X_q) = \prod_i p(x_i\mid H,\,x_{视觉 token 通过 self-attention 被每个文本 token「看到」。一句话：图像 → 576 个伪词 → 和文字排成一队 → LLM 照常说话。

🔥 视觉 token 怎么「塞进」文本序列（面试必考）

输入里先放一个特殊占位符 <image>（对应一个保留 token id）。前向时：先用 LLM 的 embedding 层把文本 token 变成词向量，再把序列中那一个 <image> 位置，替换/展开成 Projector 输出的 576 个视觉向量。所以「1 个占位符 → 576 个视觉 token」，序列长度相应变长。注意：替换的是输入 embedding，不是 token id——视觉向量根本不在词表里。

import torch IMAGE_TOKEN_INDEX = -200 # <image> 占位符的特殊 id（不在正常词表里） def encode_images(self, images): feats = self.vision_tower(images) # CLIP ViT -> (B, 576, 1024) return self.mm_projector(feats) # MLP -> (B, 576, 4096) def prepare_inputs_labels_for_multimodal(self, input_ids, labels, images): image_features = self.encode_images(images) # (B, 576, 4096) new_embeds, new_labels = [], [] for ids, lab, feat in zip(input_ids, labels, image_features): emb = self.embed_tokens(ids.clamp(min=0)) # 文本 -> (L, 4096) pos = (ids == IMAGE_TOKEN_INDEX).nonzero()[0].item() # 找 <image> # 在 embedding 层把 1 个占位符展开成 576 个视觉向量 emb = torch.cat([emb[:pos], feat, emb[pos+1:]], dim=0) # 视觉 token 的 label 设为 -100（不计 loss） vlab = torch.full((feat.size(0),), -100, device=lab.device) lab = torch.cat([lab[:pos], vlab, lab[pos+1:]], dim=0) new_embeds.append(emb); new_labels.append(lab) return pad_and_stack(new_embeds, new_labels) # 处理变长 + attention_mask
🔥 四个必看的点

① encode_images():vision_tower(CLIP) + mm_projector(MLP),出 (B,576,4096)。② IMAGE_TOKEN_INDEX = -200:负数 id,故意不在词表里——所以必须在 embedding 层替换,不能走正常 embedding。③ 合并发生在 prepare_inputs_labels_for_multimodal():用 torch.cat 把视觉向量插进占位符位置。④ 视觉 token 的 label=-100:自回归 loss 不算在图像上(呼应 D14 的 loss 落点)。

📊 InternVL：大 ViT + 动态分辨率 + Pixel Shuffle

学习目标

InternVL 代表「增强视觉编码器」这条路线——不用现成的小 CLIP,自己训一个更大更强的 ViT。学完今天你应能:(1) 说清「大 ViT 路线」vs「现成 CLIP 路线」的取舍;(2) 讲清动态分辨率怎么处理高清/任意长宽比的图;(3) 算出动态分辨率 + Pixel Shuffle 后的 token 数;(4) 知道 InternVL 为什么在 OCR、文档、中文上强。

一、两条路线之争：视觉塔要不要自己训

D14 的 LLaVA 用现成 CLIP ViT-L(0.3B)当视觉塔,简单够用,但视觉能力被 CLIP 封顶。InternVL 走另一条路:自己从头训一个 6B 参数的 InternViT,视觉能力天花板大幅抬高。代价是训练成本巨大——这是典型的「买现成 vs 自研」工程权衡。

🔥 InternVL 的四个关键点

① InternViT-6B:专为多模态训练的 6B 视觉编码器(CLIP ViT-L 仅 0.3B),视觉特征更强。② 动态高分辨率:按原图长宽比切成若干 448×448 tile + 一张缩略全图,既看清细节又保留全局。③ Pixel Shuffle 压缩:每 tile 的 1024 token 折叠成 256(÷4),控制总 token 数(呼应 D13)。④ ViT–MLP–LLM 范式:结构仍是 LLaVA 那套,只是把视觉塔换成大家伙。

💡 为什么 InternVL 在 OCR / 文档 / 中文上强

动态高分辨率让它能「看清」密集小字(OCR、文档、图表),大视觉塔 + 海量中文图文数据让中文场景表现突出。对你来说,上海 AI Lab 的开源模型,中文友好、文档/可复现性好,做实验和写论文引用都顺手。

二、动态分辨率 + 压缩：token 数怎么算

📐 推导 动态分辨率 + Pixel Shuffle 的 token 预算
动态分辨率（InternVL 1.5）

把任意长宽比/高分辨率图切成若干 $448\times448$ tile。例：$1344\times896$ 的图 $\approx 3\times2 = 6$ 个 tile，再 +1 张缩略全图 $= 7$ 块。每块（patch=14）：$(448/14)^2 = 32\times32 = 1024$ token。

不压缩 vs Pixel Shuffle（÷4，呼应 D13）
$$\underbrace{7\times1024 = 7168}_{\text{不压缩 ⚠ 太多}} \quad\xrightarrow{\ \text{Pixel Shuffle }\div4\ }\quad \underbrace{7\times256 = 1792}_{\text{✓ 可控}}$$

InternViT-6B vs CLIP ViT-L：参数量 $6\mathrm{B}$ vs $0.3\mathrm{B}$（约 20 倍）→ 视觉特征更强，但显存/算力开销大得多，工程上常用蒸馏 / 量化用起来。

📊 M-RoPE：给视觉 token 一个 3D 位置 (t,h,w)

学习目标

Qwen-VL 是中文多模态的标杆,Qwen2-VL 的 M-RoPE 是其代表性创新。学完今天你应能:(1) 说清标准 1D RoPE 处理图像/视频「位置感」的不足;(2) 默写 M-RoPE 怎么把 head 切成 t/h/w 三段、文本如何退化;(3) 讲清 Qwen-VL→Qwen2-VL 的架构演进(resampler → 动态分辨率 + M-RoPE);(4) 用 HF 跑通 Qwen2-VL 推理。

一、动机：1D 位置编码「看不懂」二维图像

LLM 的 RoPE 给每个 token 一个 1D 位置 m(第几个 token)。但图像 patch 是二维排布的——把它们拉平成一维序列后,模型就丢了「这个 patch 在左上还是右下」的信息;视频还多了「第几帧」。M-RoPE 的思路:给每个 token 一个 (t,h,w) 三维位置,让模型天然感知时间和空间。

🔥 Qwen-VL 系列的架构演进

Qwen-VL(2023):ViT(OpenCLIP bigG) + 一个 position-aware adapter(单层 cross-attention,把视觉 token 压到 256) + Qwen LLM;原生支持 grounding、OCR。

Qwen2-VL(2024):两大升级——① Naive Dynamic Resolution:任意分辨率 → 动态数量的视觉 token(不再强制固定 256);② M-RoPE:3D 位置编码,统一处理文本/图像/视频。

这条线让 Qwen-VL 在中文、OCR、文档、视频上都很能打,是国内做实验最常用的强基线之一。

二、M-RoPE 推导

📐 推导 Multimodal RoPE：把 1D 位置升级成 (t,h,w)

标准 RoPE：每个 token 一个 1D 位置 $m$，对 $q,k$ 每对维度施加角度 $m\theta$ 的旋转。M-RoPE：每个 token 一个 3D 位置 $(t,h,w)$ —— $t$ 时间（帧号）、$h$ 垂直（行）、$w$ 水平（列）。

把 head 维度 d 切三段，各编一种位置
$$\underbrace{\text{dim}[0:\tfrac{d}{3}]}_{\text{用 }t}\quad \underbrace{\text{dim}[\tfrac{d}{3}:\tfrac{2d}{3}]}_{\text{用 }h}\quad \underbrace{\text{dim}[\tfrac{2d}{3}:d]}_{\text{用 }w}$$
不同模态如何取 (t,h,w)

文本：$t=h=w=$ 当前序列位置 → 退化成普通 1D RoPE（向后兼容！）。图像：$t$ 固定，$(h,w)=$ patch 行列坐标。视频：$t=$ 帧号，$(h,w)=$ 该帧内 patch 行列。

效果：模型天然知道「patch 在左上还是右下」「这是第几帧」，对 grounding、视频时序理解尤其关键。

二、数据配比与清洗（实践要点）

📐 要点 数据工程里真正影响效果的几件事

📊 两种 Grounding 方案：坐标文本化 vs 特殊 token

学习目标

MLLM 不只能「看图说话」,还能指哪看哪——输出 bounding box 定位特定物体。这正是你 CV 检测背景的主场。学完今天你应能:(1) 说清两种 grounding 方案(坐标文本化 vs 特殊 token+回归头)的取舍;(2) 解释坐标为什么要归一化到 [0,1000];(3) 用 Qwen-VL 跑一次 grounding;(4) 把它和传统检测器的差异讲清楚。

一、让 LLM「说出」物体在哪

传统检测器输出固定类别的框;而 MLLM 可以按任意自然语言定位(「穿红衣服的那个人」「左边第二只猫」),这叫 referring expression / visual grounding。关键问题:LLM 只会生成 token,怎么让它「输出坐标」?

🔥 两种主流方案

① 坐标文本化(Qwen-VL、Shikra):直接让 LLM 把坐标当普通文本生成,如 "猫 [120,80,340,360]"。坐标归一化到 [0,1000],与图像实际像素无关。无需改结构、简单有效,但精度受 tokenizer 对数字的切分方式限制。

② 特殊 token + 回归头(Kosmos-2):让 LLM 输出 <box> 特殊 token,再接一个坐标回归头输出连续值。更精确,但要改模型结构、加训练目标,更复杂。

💡 和你的检测背景对接

归一化坐标 [0,1000] ≈ 你熟悉的 cxcywh/xyxy 相对坐标;回归头方案本质就是把检测头接到 LLM 上。差别在于:MLLM 的「类别」是开放的自然语言,不再是固定 80 类。这也是它比传统检测器灵活、但定位精度往往不如专用检测器的原因。

学习目标

一、为什么要「拼模型」

MLLM 擅长理解模糊的人话并定位(「那只躲在角落的猫」),但它输出的 bbox 不够精细;SAM 擅长像素级精确分割,但它不懂语言、需要 prompt(点/框)。把两者串起来:MLLM/Grounding 出 bbox → SAM 拿 bbox 当 prompt 出 mask,各取所长。

🔥 典型 pipeline 与 SAM 的 prompt 机制

流程:用户说「分割那只猫」→ Grounding 模型(MLLM 或 Grounding DINO)理解并输出 bbox → SAM 用这个 bbox 作为 box prompt → 输出精确 mask。

SAM 的关键:它是一个 promptable 分割模型,接受点 / 框 / 粗 mask 作为提示,输出对应物体的精确掩码——所以谁来给 prompt 都行,这才让「语言→分割」得以拼接。

💡 这就是 Agent 的雏形

「大模型理解意图 + 专业模型执行」正是 Agent 调用工具的最小形态(Week 06 会系统讲)。你完全可以把 SAM 换成你的低光增强模型:MLLM 判断「这是低光退化图」→ 调用增强工具 → 再理解——这就是一个结合你背景的 Agent 研究切口。

一、从「先 OCR 再理解」到「直接理解」

传统做法是 检测→识别→版面分析→喂 LLM 的多模块流水线:每一级都可能出错,误差逐级累积,部署也繁琐。OCR-free 的思路:让 MLLM 直接「看懂」整张文档——读字、回答、甚至转成 Markdown 表格,一步到位。代价是:文档小字密集,必须喂高分辨率(直接回扣 D13 的 token 压缩、D16 的动态分辨率)。

📊 视频 → 帧采样 → token（核心矛盾：数量爆炸）

学习目标

视频 = 图像序列 + 时间维度。学完今天你应能:(1) 说清视频处理的核心矛盾(帧数 × 每帧 token);(2) 对比三种主流方案;(3) 把视频和 D17 的 M-RoPE 时间维联系起来;(4) 用 Qwen2-VL 跑一次视频问答。

一、视频的核心矛盾：token 怎么都不够用

处理视频最朴素的做法:均匀抽 N 帧,每帧当图像编码,token 拼起来。但问题立刻来了:8 帧 × 576 token = 4608,16 帧就快上万——总 token = 帧数 × 每帧 token,这是 D13 token 爆炸问题的「时间放大版」。于是只能在「看更久(更多帧) vs 看更清(每帧更多 token)」之间拉扯。

🔥 三种主流方案

① 均匀帧采样:等间隔抽 N 帧,各自编码后拼接。最简单最常用,但帧少会漏掉关键瞬间,帧多则 token 爆炸。

② 时序 token 压缩:相邻帧画面相似 → 视觉 token 高度冗余 → 合并/池化掉重复部分(类似 D13 的 token merging,但跨时间)。

③ SlowFast 思路:少数「慢」帧保留每帧细节(高 token),多数「快」帧只取动态信息(低 token),兼顾清晰与时长。

💡 和 M-RoPE 的联系（回扣 D17）

视频 token 不仅要知道「在画面哪个位置」(h,w),还要知道「在第几帧」(t)——这正是 Qwen2-VL 的 M-RoPE 把位置升到 3D (t,h,w) 的用武之地。没有时间维,模型分不清「先后顺序」,无法理解动作和因果。

学习目标

一、为什么模型会「脑补」

MLLM 的底座是个强大的 LLM,它从海量文本里学到了强烈的语言先验(「草地上常有羊」「厨房里常有刀」)。当解码时语言先验的权重压过了实际视觉证据,模型就会顺着「常识」把不存在的东西说出来——尤其在长描述的后半段,越说越放飞。

🔥 四类成因 + 主流缓解

成因:① 语言先验过强——根因,忽略视觉直接按常识猜;② 数据偏差——训练 caption 里「羊+草地」总共现,学成强关联;③ 分辨率不够——没看清就乱猜(回扣 D13/D16);④ 长输出累积——自回归越往后越依赖已生成文本而非图像。

缓解:① RLHF-V / LLaVA-RLHF:用人类反馈惩罚幻觉;② 对比解码 VCD:对比「正常图」和「加噪图」的输出,扣掉与图像无关的语言先验;③ 提分辨率 + 高质量数据;④ POPE 等评测持续监控。

D26LLM Agent 框架：ReAct、Tool Use、Planning▶
📊 ReAct：Thought → Action → Observation 循环

学习目标

Agent 的核心:感知 → 推理 → 行动 → 观察 的循环。学完今天你应能:(1) 讲清 ReAct 范式、它和固定 pipeline 的本质区别;(2) 说清 Function Calling / Tool Use 的机制;(3) 自己写一个最小 ReAct loop;(4) 把它和你 CV+Agent 的工作对应起来。

一、从「固定流程」到「动态决策」

传统 CV pipeline 是写死的流程:检测→分类→输出。Agent 不一样:LLM 在每一步先「想」(Thought),再决定「做什么」(Action),执行后看「结果」(Observation),再据此想下一步——流程不是写死的,而是根据中间结果动态生成的。这就是 ReAct(Reason + Act)。

🔥 ReAct 范式 + Function Calling

ReAct 循环:Thought → Action → Observation → Thought → …,直到信息足够就给 Answer。每个 Action 都是一次工具调用。

Function Calling / Tool Use:模型输出结构化的函数调用(JSON),外部系统执行后把结果喂回模型。例:模型输出 {"name":"enhance_image","args":{"path":"dark.jpg"}} → 系统跑图像增强 → 把结果返回 → 模型继续推理。LLM 负责「决策」,工具负责「执行」(正是 D22 的延伸)。

💡 和你的 CV+Agent 工作对接

你已经在做 CV+Agent,这里只是把理论补齐。一个直接的升级:把流水线里写死的「先增强再检测」换成 MLLM 自己判断「这张图退化严重 → 先调增强工具 → 再检测」——让决策从硬编码变成模型推理,泛化性大增。

二、动手：最小 ReAct loop

import json TOOLS = { "enhance_image": lambda path: f"已增强 {path}，亮度+40%", "detect_objects": lambda path: "检测到: 1辆车, 2个人", } def react(llm, question, max_steps=5): scratch = question for _ in range(max_steps): out = llm(scratch) # LLM 生成 Thought + Action(JSON) if out.get("answer"): # 信息够了 → 收尾 return out["answer"] act = out["action"] # {"name":..., "args":...} obs = TOOLS[act["name"]](**act["args"])# 执行工具 → Observation scratch += f"\nAction: {json.dumps(act, ensure_ascii=False)}\nObservation: {obs}" return "达到最大步数" # LLM 每一步看着 scratch（含历史 Thought/Action/Observation）决定下一步—— # 这就是 Agent 的全部秘密：把"历史 + 工具结果"喂回去，让它自己接着想。

📊 Multi-Agent 三种协作模式

学习目标

单 Agent 能力有限,Multi-Agent 让多个专才协作完成复杂任务。学完今天你应能:(1) 区分管道/讨论/层级三种协作模式及适用场景;(2) 说清各自的代价(通信成本、失控风险);(3) 知道主流框架;(4) 写一个最小的层级式分派骨架。

一、为什么需要「一群」Agent

让一个 Agent 既当规划者、又当程序员、又当审稿人,容易顾此失彼。把角色拆开——每个 Agent 专注一件事,再让它们协作,复杂任务更可控、可调试。代价是:Agent 之间要通信,轮次多了 token 成本高,还可能互相带偏(失控)。

🔥 三种协作模式 + 框架

① 管道式:A→B→C 接力,每个 Agent 处理上一个的输出(像流水线)。简单可控,但错误会顺着传。

② 讨论式:多个 Agent 各自推理,再投票/汇总(类似 ensemble),适合需要多视角、纠错的任务。

③ 层级式:Manager 拆解任务、分派给 Worker、收集汇报(像项目经理带团队),适合可分解的大任务。

框架:AutoGen(微软,对话式多 agent)、CrewAI(角色编排)、LangGraph(把多 agent 表达成状态图)。

💡 和你方向的连接

一个低光视觉任务可以拆成:质量评估 Agent(判退化程度)→ 增强 Agent(调工具复原)→ 理解 Agent(检测/识别)→ 审查 Agent(校验结果)。这正是层级/管道式的天然落地,也比单模型更鲁棒。

📊 多模态 CoT：先看 → 再想 → 答

学习目标

思维链(CoT)让模型「先想再答」;多模态版还要先「看准」。学完今天你应能:(1) 说清文本 CoT 与多模态 CoT 的差别;(2) 解释「错误传播」为什么是多模态推理的命门(回扣 D25 幻觉);(3) 写一个让模型「先描述再推理」的 prompt;(4) 知道前沿的视觉推理思路。

一、为什么多模态推理更难

文本 CoT 就是 step by step 地想。但多模态多了一层:模型得先把图像「看准」,再在看到的内容上推理。一旦第一步「看」错了(幻觉),后面想得再有条理,结论也错——这就是 错误传播。所以多模态推理的关键不只是「会想」,而是「视觉地基稳不稳」。

🔥 多模态 CoT 的结构与挑战

典型三段:① 描述(我看到了什么)→ ② 推理(基于看到的一步步推)→ ③ 答案。把「感知」和「推理」显式分开,比直接出答案更准、更可解释。

核心挑战:第①步若产生幻觉,错误会沿着推理链放大(D25);所以缓解幻觉 = 提升推理。前沿做法还包括让模型边推理边「回看」图像(visual grounding 进推理链)、以及用 RL 强化长链视觉推理。

💡 你的研究角度

退化图像让第①步「看」更不可靠 → 错误传播更严重。「退化条件下多模态推理的鲁棒性 / 不确定性感知推理」(看不清时让模型「存疑」而非硬答)是你背景的好切口,直接连 D25。

📊 视觉 Token 压缩的四条路

学习目标

在不掉点的前提下减少视觉 token 数量——这是你 CV 背景最容易切入的研究方向之一。学完今天你应能:(1) 说清视觉 token 为什么冗余、压缩为什么省算力(回扣 D13);(2) 区分四类压缩方法及取舍;(3) 实现一个最简单的相似度合并;(4) 想清你「退化感知压缩」的研究切口。

一、为什么能压、压了为什么快

相邻 patch 画面相似 → 视觉 token 高度冗余;而 LLM 的 attention 是 O(L²),序列减半计算约降 4 倍(回扣 D13/D24)。所以「少而精」既省 context 又提速——只要别把关键信息(小目标、文字)压没。

🔥 四类主流方法

① Token Merging(ToMe):按相似度把冗余 token 两两合并(无需训练即可用)。② Token Pruning(FastV):按 attention 分数丢弃「没人看」的 token,且发现 LLM 浅层后视觉 token 重要性骤降。③ Learnable Resampler(Q-Former/Perceiver):用固定数量可学习 query 把任意多 token 压到定额(回扣 D13)。④ Early Exit / 自适应:简单图给少量 token、复杂图给更多,按需分配。

💡 你的研究切口（强相关）

现有压缩几乎都在清晰图上设计。问题来了:低光/退化图像里,哪些 token 才是信息性的?退化是否改变了 token 的重要性分布? 「退化/质量感知的视觉 token 压缩」= 你的图像质量背景 × 效率前沿,是一个干净、可发论文的切口(连 D13/D34)。

二、动手：最简单的相似度合并（ToMe 思想）

import torch import torch.nn.functional as F def token_merge(tokens, keep_ratio=0.5): """tokens: (N, D) 视觉 token；按相似度合并冗余，保留 keep_ratio""" x = F.normalize(tokens, dim=-1) sim = x @ x.T # 两两余弦相似度 sim.fill_diagonal_(-1) N = tokens.size(0); keep = int(N * keep_ratio) # 每个 token 与最相似邻居的相似度 → 越相似越「可被合并」 nn_sim, nn_idx = sim.max(dim=-1) drop = nn_sim.topk(N - keep).indices # 最冗余的那批 drop_set = set(drop.tolist()) merged = tokens.clone() for i in drop.tolist(): # 把冗余 token 并入其最近邻 merged[nn_idx[i]] = (merged[nn_idx[i]] + tokens[i]) / 2 keep_idx = [i for i in range(N) if i not in drop_set] return merged[keep_idx] # (keep, D) print(token_merge(torch.randn(576, 1024)).shape) # → (288, 1024)，省一半

📊 VLA：Vision → Language → Action

学习目标

VLA(Vision-Language-Action)把 MLLM 从「会说」推进到「会做」。即使你组里不做机器人,这个思路也很值钱。学完今天你应能:(1) 说清 VLA 的结构、它和 MLLM 的关系;(2) 解释「动作当 token 预测」的核心洞察;(3) 把它迁移到 GUI/驾驶等非机器人场景;(4) 知道 RT-2 / OpenVLA 的代表性。

一、把「动作」也当成 token

MLLM 的输出是文字 token。VLA 的关键一招:把机器人动作(位移 Δx,Δy,Δz、旋转、夹爪开合)离散化成 token,接到同一个词表里。于是「预测下一步动作」就和「预测下一个词」是同一件事——直接复用了 LLM 强大的序列建模和世界知识。这就是 RT-2 的核心思想。

🔥 VLA 结构与代表模型

结构:Vision(看) → Language(理解指令) → Action(输出动作 token)。主干就是一个 VLM,只是输出空间从「文字」扩到「动作」。

代表:RT-2(Google,把 VLM 微调成机器人策略,动作即 token) · OpenVLA(开源 7B VLA,可复现) · RT-1(更早的机器人 Transformer,纯模仿学习)。

迁移:这套「感知→决策→动作」对 GUI Agent(D27,动作=click/type)、自动驾驶(动作=方向/油门)、游戏 AI 同样成立——不一定要真机器人。

💡 给你的视角

你不做机器人也别跳过:VLA 证明了「MLLM 可以直接输出结构化决策」,这正是你 CV+Agent(D27/D30)的理论靠山。一个轻量切口:退化视觉输入下 VLA/GUI 策略的鲁棒性——看不清时动作会不会失准。

# VLA 的核心：把连续动作离散成 token，复用 LLM 的下一 token 预测 # 动作向量（7 维：3 平移 + 3 旋转 + 1 夹爪）→ 每维分 256 桶 → 离散 token def discretize_action(action, bins=256, low=-1.0, high=1.0): idx = ((action - low) / (high - low) * (bins - 1)).round().clamp(0, bins-1) return idx.int() # 例: [128,140,...] 当作词表里的特殊 token id # 推理：VLM 看图+指令 → 自回归生成「动作 token」→ 反离散化成真实动作 # action_tokens = vlm.generate(image, "把红色方块放进盒子") # action = undiscretize(action_tokens) # 送给机器人/仿真执行 # 训练：和语言建模完全一样——拿 (图像, 指令, 动作序列) 做下一 token 预测

训大模型的主要瓶颈是显存:模型参数 + 优化器状态 + 梯度 + 激活,动辄上百 GB。核心思路只有一个——用「算力/通信」换「显存」,且尽量不丢精度。四大手段层层叠加,就能把「放不下」的训练塞进有限的卡。

🔥 四大技术（对应 D20 命令）

① DeepSpeed ZeRO / FSDP:把优化器状态(ZeRO-1)、梯度(ZeRO-2)、参数(ZeRO-3)切分到多卡,单卡只存一份(对应 --deepspeed zeroN.json)。② 混合精度 BF16:用半精度算、关键处保 FP32,省显存又提速(对应 --bf16)。③ 梯度检查点:前向不存所有激活,反向时重算——用计算换显存。④ FlashAttention:把 attention 的显存从 O(N²) 降到 O(N)(底层算子,长序列尤其关键)。再叠加 LoRA(D8/D20)只训低秩增量。

二、FlashAttention 核心思想

📐 推导 FlashAttention：为什么显存从 O(N²) 降到 O(N)
标准 Attention 的内存瓶颈
$$S = QK^\top \in \mathbb{R}^{N\times N}\ \xrightarrow{\ \text{softmax}\ }\ P \in \mathbb{R}^{N\times N}\ \xrightarrow{\ \cdot V\ }\ O$$

$N{=}4096$ 时 $S$ 这张表就要 ~64MB（还要存梯度）；把完整的 $N\times N$ 中间矩阵反复搬进/搬出 HBM（显存），IO 成了瓶颈。

FlashAttention 的两招

① 分块 tiling：把 $Q,K,V$ 切小块，只在 SRAM（片上高速缓存）里算 → 永不在 HBM 物化完整 $N\times N$ 矩阵。② online softmax：边读块边维护 running max / running sum，增量更新输出，无需看到整行才归一化。

结果：显存 $O(N^2)\to O(N)$；减少 HBM 读写，实测快 $2\text{–}4\times$；且是精确 attention，不是近似。FlashAttention-2/3 进一步优化并行度与新硬件（H100）利用率。

三、自测 / 经验 / 误区

💡 经验

第一版实验不需要完美。目标是验证 idea 有没有 signal(哪怕只提升 1–2 个点),然后迭代。很多好论文都是从一个微小但稳定的正向信号开始的。先小步快跑,信号确认了再上大实验。

⚠️ 常见误区

① 一次改太多——赢输都无法归因。② 没有「关掉就等于 baseline」的开关——消融做不干净。③ 一上来就跑大实验——慢、贵、改一次等一天。④ 把噪声当信号——+0.3 点可能只是随机波动,要多 seed / 看方差。
