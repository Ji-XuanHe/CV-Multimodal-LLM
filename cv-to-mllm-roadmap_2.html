P01 深度学习核心三件套：前向传播、损失函数、反向传播 ▶

学习目标

理解神经网络最基础的工作方式——数据怎么流过网络（前向），怎么衡量好坏（损失），怎么更新参数（反向传播 + 梯度下降）。

🔥 核心概念

前向传播（Forward Pass）：输入 x → 逐层计算 → 输出预测 ŷ。每一层做的事本质上就是 output = activation(W · input + b)。

损失函数（Loss）：衡量预测 ŷ 和真实标签 y 的差距。分类用交叉熵 CrossEntropyLoss，回归用均方误差 MSELoss。

反向传播（Backpropagation）：用链式法则从损失往回算每个参数的梯度 ∂L/∂W，然后用梯度下降更新参数。

📐 推导 链式法则与梯度下降（手推一遍加深理解）
假设一个两层网络：
  z₁ = W₁ · x + b₁       (线性变换)
  h  = ReLU(z₁)           (激活函数)
  z₂ = W₂ · h + b₂
  ŷ  = softmax(z₂)        (输出概率)
  L  = -∑ yᵢ log(ŷᵢ)     (交叉熵损失)

反向传播（链式法则，从后往前推）：
  ∂L/∂z₂ = ŷ - y                          (softmax + CE 的简洁梯度)
  ∂L/∂W₂ = (∂L/∂z₂) · hᵀ                  (对 W₂ 的梯度)
  ∂L/∂h  = W₂ᵀ · (∂L/∂z₂)                 (传回上一层)
  ∂L/∂z₁ = (∂L/∂h) ⊙ ReLU'(z₁)            (⊙ 逐元素乘)
  ∂L/∂W₁ = (∂L/∂z₁) · xᵀ

参数更新（梯度下降）：
  W ← W - lr × ∂L/∂W     (lr 是学习率)

常用优化器：
  SGD:  最基础
  Adam: 自适应学习率，目前最常用
  AdamW: Adam + 权重衰减（大模型标配）

P02 卷积神经网络（CNN）：从 LeNet 到 ResNet ▶

学习目标

理解 CNN 的基本操作（卷积、池化、特征图），以及 ResNet 的残差连接——这个思想在 Transformer 中同样核心。

🔥 CNN 三个关键概念

卷积核（Kernel/Filter）：一个小的可学习矩阵（如 3×3），在输入图像上滑动做局部特征提取。参数共享 + 局部连接 = 大幅减少参数量。

特征图（Feature Map）：一个卷积核滑过整张图后生成一张特征图。多个卷积核 = 多个特征图 = 多通道输出。

残差连接（ResNet）：output = F(x) + x。让网络学习残差而非完整映射，解决深层网络训练困难的问题。这个思想在 Transformer 的每一层都在用！

📐 推导 卷积操作的数学定义与输出尺寸计算
2D 卷积操作（单通道简化版）：
  输入 X ∈ ℝ^{H×W}，卷积核 K ∈ ℝ^{k×k}
  输出 Y[i,j] = ∑_m ∑_n X[i+m, j+n] · K[m, n]

输出尺寸公式（面试常考）：
  H_out = (H_in - k + 2·padding) / stride + 1
  
例：输入 224×224，卷积核 3×3，padding=1，stride=1
  → H_out = (224 - 3 + 2) / 1 + 1 = 224   （尺寸不变）

例：输入 224×224，卷积核 7×7，padding=3，stride=2
  → H_out = (224 - 7 + 6) / 2 + 1 = 112   （尺寸减半）

多通道卷积：
  输入 C_in 个通道，每个卷积核大小 = C_in × k × k
  N 个卷积核 → 输出 N 个通道
  参数量 = N × C_in × k × k + N（bias）

P03 注意力机制：Scaled Dot-Product Attention 与 Multi-Head ▶

学习目标

注意力机制是 Transformer 的灵魂。彻底理解 Q/K/V 的含义、注意力分数的计算、以及为什么要多头。

📐 推导 注意力机制完整推导（最重要的推导之一）
═══ 核心直觉 ═══
注意力回答的问题：序列中的每个位置应该「关注」其他哪些位置？

类比：你在图书馆找书
  Query (Q)：你要找的主题（「我想找关于猫的书」）
  Key (K)  ：每本书封面上的标签（「动物」「烹饪」「历史」）
  Value (V)：书的实际内容

  注意力 = 用 Q 和每个 K 比对相关度 → 加权提取 V 的内容

═══ Scaled Dot-Product Attention ═══
输入：Q ∈ ℝ^{n×d_k}, K ∈ ℝ^{m×d_k}, V ∈ ℝ^{m×d_v}

Step 1: 计算相似度分数
  S = Q · Kᵀ ∈ ℝ^{n×m}     每对 (query, key) 的点积

Step 2: 缩放（为什么？）
  S = S / √d_k
  原因：d_k 很大时，点积的方差 ≈ d_k，
  导致 softmax 输出接近 one-hot，梯度消失。
  除以 √d_k 让方差回到 1。

Step 3: Softmax 归一化
  A = softmax(S)    每行和为 1，即每个 query 的注意力权重

Step 4: 加权求和
  Output = A · V ∈ ℝ^{n×d_v}

合在一起：
  Attention(Q,K,V) = softmax(QKᵀ / √d_k) · V

═══ Multi-Head Attention ═══
为什么要多头？单个注意力只能学一种「关注模式」。
多头让模型同时关注不同方面（语法、语义、位置...）

  head_i = Attention(QWᵢᴾ, KWᵢᴷ, VWᵢⱽ)
  MultiHead = Concat(head₁, ..., head_h) · Wᴼ

h 个头，每个头的维度 d_k = d_model / h
例：d_model=768, h=12 → 每个头 64 维
🔥 Self-Attention vs Cross-Attention

Self-Attention：Q、K、V 都来自同一个序列。每个 token 看序列中所有其他 token。ViT 和 GPT 的核心。

Cross-Attention：Q 来自一个序列，K/V 来自另一个序列。用于不同模态之间的交互（后面多模态会用到）。

P04 Vision Transformer（ViT）：把图像变成序列 ▶

学习目标

ViT 的核心思想极其简单——把图像切成小块（patch），当作「单词」，然后用标准 Transformer 处理。这个思想直接奠定了后面所有多模态模型的基础。

📐 推导 ViT 完整流程（从图像到分类结果）
═══ Step 1: Patch Embedding ═══
输入图像 x ∈ ℝ^{H×W×C}，如 224×224×3

切成 N 个 patch，每个 patch 大小 P×P
  N = (H/P) × (W/P) = (224/16) × (224/16) = 196 个 patch

每个 patch 展平为向量：P×P×C = 16×16×3 = 768 维
再通过线性投影映射到 d_model 维：
  patch_embed = Linear(P²·C, d_model)

═══ Step 2: 添加特殊 token 和位置编码 ═══
在序列最前面加一个 [CLS] token（可学习）：
  序列变为 [CLS, patch₁, patch₂, ..., patch₁₉₆]
  长度 = 197

加上可学习的位置编码（每个位置一个 d 维向量）：
  z₀ = [x_cls; patch₁E; ...; patch_N·E] + E_pos
  E_pos ∈ ℝ^{(N+1)×d}

═══ Step 3: Transformer Encoder ═══
标准的 L 层 Transformer Encoder（和 BERT 一样）：
  每层：LayerNorm → Multi-Head Self-Attention → 残差
       → LayerNorm → FFN (MLP) → 残差

注意：这里是双向注意力（不是 GPT 的因果注意力）
每个 patch 可以看到所有其他 patch

═══ Step 4: 分类头 ═══
取 [CLS] token 的最终表示 → MLP Head → 类别概率
  y = MLP(LayerNorm(z_L[0]))

参数量估算（ViT-Base）：
  d=768, L=12 层, h=12 头
  ≈ 86M 参数（和 ResNet-50 的 25M 相比更大）
🔥 ViT 的关键洞察

CNN vs ViT 的本质差异：CNN 通过卷积核天然具有局部感受野和平移不变性；ViT 没有这些归纳偏置（inductive bias），完全靠数据学习。所以 ViT 在小数据集上不如 CNN，但在大数据集上远超 CNN。

为什么 ViT 对多模态如此重要：ViT 让图像和文本统一成了相同的表示形式——token 序列。这为后面把图像 token 和文本 token 拼在一起送入 LLM 铺平了道路。

D01 Encoder vs Decoder：从 ViT 到 GPT 的思维转变 ▶

学习目标

理解 Encoder-only（BERT / ViT）、Decoder-only（GPT）、Encoder-Decoder（T5）三种架构的本质差异，搞清楚为什么现在主流 LLM 都选择 decoder-only。

🔥 核心概念

Causal Attention（因果注意力）是 decoder-only 和你熟悉的 ViT 最根本的区别。ViT 中每个 patch token 可以看到所有其他 token（双向注意力），GPT 中每个 token 只能看到它之前的 token（单向），通过 causal mask 实现。

理解这一点就理解了「自回归生成」——模型一个 token 一个 token 地预测下一个词。

📐 推导 Causal Attention 与标准 Self-Attention 的区别
标准 Self-Attention（你在 ViT 里熟悉的）：
  Attention(Q, K, V) = softmax(QKᵀ / √d_k) · V

Causal Self-Attention（GPT 使用的）：
  Attention(Q, K, V) = softmax(QKᵀ / √d_k + M) · V
  其中 M 是上三角 mask 矩阵，M_ij = 0 if i≥j, else -∞

效果：位置 i 的 token 只能 attend 到 [0, 1, ..., i]，
看不到未来的 [i+1, i+2, ...] 位置。

D02 Tokenization：BPE、SentencePiece 与词表设计 ▶

学习目标

理解文本如何变成 token ID 序列。这是 CV 人最容易忽略的部分——图像天然是连续的，但语言模型的输入是离散的整数序列。

🔥 核心概念

BPE（Byte Pair Encoding）是目前主流的 tokenizer 算法。核心思路：从字符级开始，不断合并出现频率最高的 pair，直到词表达到预设大小。

词表大小直接影响：嵌入层参数量、序列长度（词表越大同一段文本 token 越少）、多语言能力。

📐 推导 BPE 算法完整步骤（需要手动走一遍）
初始词表：所有单个字符 {'l','o','w','e','r','n','s','t','i','d',...}
语料频率统计：l o w = 5次, l o w e r = 2次, n e w e s t = 6次 ...

迭代过程：
  Step 1: 统计所有相邻 pair 的频率
    ('e','s') 出现 9 次 → 最高 → 合并为 'es'
  Step 2: 更新语料，重新统计
    ('es','t') 出现 9 次 → 合并为 'est'
  Step 3: 继续...
  直到词表大小 = 目标值（如 32000）

现代变体：
  - Byte-level BPE（GPT-2/3/4）：以 byte 而非 unicode 字符为起点
  - SentencePiece（Llama/Qwen）：直接在原始文本上训练，不需要预分词

D03 GPT 完整架构：从 Embedding 到输出概率 ▶

学习目标

完整理解 GPT 系列的前向传播过程：token embedding + positional encoding → N 层 decoder block → lm_head → 概率分布。

🔥 GPT Decoder Block

结构（每层重复 N 次）：x → LayerNorm → Causal Multi-Head Self-Attention → 残差连接 → LayerNorm → FFN（MLP）→ 残差连接 → output

和 ViT Block 的区别：(1) attention 有 causal mask；(2) 没有 cross-attention（纯 decoder）；(3) 通常用 Pre-Norm（ViT 也是）。

📐 推导 完整前向过程与参数量估算（面试常考）
完整前向过程（对照 nanoGPT 代码理解）：

1. Token Embedding: E ∈ ℝ^{V × d}，将 token ID 映射为向量
   h₀ = E[x] + PE    (PE: 位置编码)

2. Transformer Layers (×N):
   h'ₗ = hₗ + CausalMHA(LayerNorm(hₗ))
   hₗ₊₁ = h'ₗ + FFN(LayerNorm(h'ₗ))

   其中 FFN(x) = W₂ · GELU(W₁ · x)
   （现代模型如 Llama 用 SwiGLU: FFN(x) = W₂ · (SiLU(W₁x) ⊙ W₃x)）

3. 输出层:
   logits = LayerNorm(h_N) · Eᵀ   (权重共享)
   P(next_token) = softmax(logits)

参数量估算（重要！面试常考）：
  Embedding: V × d
  每层 Attention: 4 × d²（Q/K/V/O 四个投影矩阵）
  每层 FFN: 约 8d²（标准）或 ~8d²（SwiGLU）
  总参数 ≈ 12 × N × d²（N 是层数，d 是隐藏维度）
  7B 模型：N=32, d=4096 → 12 × 32 × 4096² ≈ 6.4B ✓

D04 位置编码：从 Sinusoidal 到 RoPE ▶

学习目标

Transformer 本身对位置不敏感（permutation invariant），必须注入位置信息。理解三代位置编码的演进。

📐 推导 三代位置编码对比（RoPE 重点理解）
═══ 第一代：Sinusoidal（原始 Transformer / ViT）═══
  PE(pos, 2i) = sin(pos / 10000^{2i/d})
  PE(pos, 2i+1) = cos(pos / 10000^{2i/d})
  加到 embedding 上：h₀ = E[x] + PE
  问题：绝对位置，无法外推到训练长度之外

═══ 第二代：ALiBi（BLOOM）═══
  不加到 embedding，而是加到 attention score 上：
  Attention_ij += -m × |i - j|
  m 是每个 head 不同的斜率
  简单但有效，天然支持外推

═══ 第三代：RoPE（Llama/Qwen/大多数现代模型）═══
  核心思想：用旋转矩阵编码相对位置
  对 q, k 向量在每对维度上做旋转：
  [q_{2i}]     [cos(mθᵢ)  -sin(mθᵢ)] [q_{2i}]
  [q_{2i+1}] = [sin(mθᵢ)   cos(mθᵢ)] [q_{2i+1}]
  其中 m 是位置，θᵢ = 10000^{-2i/d}

  qᵐ · kⁿ 的内积只依赖于 m-n（相对距离）！
  这就是「旋转位置编码」名字的由来。
🔥 为什么 RoPE 成为标准

它优雅地实现了：(1) 注意力分数只依赖相对位置；(2) 通过 NTK-aware scaling 可以外推到更长序列；(3) 计算开销极小。你后面看的所有模型（Llama、Qwen、InternVL）都用 RoPE。

D05 语言模型训练：Next Token Prediction 与采样策略 ▶

学习目标

理解预训练目标（next token prediction）的损失函数，以及推理时如何从概率分布采样生成文本。

📐 推导 预训练损失与 Perplexity
预训练损失函数：

给定序列 x = (x₁, x₂, ..., xₜ)
L = -∑ᵢ log P(xᵢ | x₁, ..., xᵢ₋₁; θ)

即标准的交叉熵损失。和你做分类任务的 CE loss 一模一样，
只不过这里「分类」的类别数 = 词表大小 V（通常 32K-150K）。

Perplexity（困惑度，评估指标）：
PPL = exp(L / T)    T 是序列长度
PPL 越低越好，直觉上代表「平均每个位置模型犹豫的选项数」。
🔥 采样策略（面试高频）

Greedy：每步选概率最大的 token。确定性但无聊。
Temperature：logits / T 后再 softmax。T<1 更确定，T>1 更随机。
Top-k：只保留概率最高的 k 个 token，其余置 0 后重新归一化。
Top-p（Nucleus）：保留累积概率达到 p 的最小 token 集合。自适应，比 top-k 更灵活。
Repetition Penalty：降低已出现 token 的概率，减少重复。

D07DPO：不需要 Reward Model 的对齐方法▶

学习目标

RLHF 太复杂（需要训练 reward model + PPO），DPO 把它简化成了一个简单的分类问题。现在大多数开源模型都用 DPO 或其变体。

📐 推导 DPO 损失函数完整推导
RLHF 的目标（Bradley-Terry 模型）：
  P(y_w ≻ y_l | x) = σ(r(x, y_w) - r(x, y_l))
  其中 y_w 是人类偏好的回答，y_l 是被拒绝的

RLHF 需要先训练 reward model r(x,y)，再用 PPO 优化策略。

DPO 的关键洞察：
  最优策略 π* 和 reward 之间有解析关系：
  r(x,y) = β log(π*(y|x) / π_ref(y|x)) + const

  代入 Bradley-Terry 模型，reward model 被消掉了！

  得到 DPO loss：
  L_DPO = -E[log σ(β log(π_θ(y_w|x)/π_ref(y_w|x))
                   - β log(π_θ(y_l|x)/π_ref(y_l|x)))]

  直觉：让模型增加好回答的概率、降低差回答的概率，
  同时不偏离参考模型太远（通过 β 控制）。

D08LoRA：低秩适配的原理与实现▶

学习目标

LoRA 是你后面做任何微调实验的基础工具，必须吃透。

📐 推导 LoRA 核心数学（务必理解）
全量微调：W' = W + ΔW    ΔW ∈ ℝ^{d×d}（参数量巨大）

LoRA 的假设：ΔW 是低秩的，可以分解为：
  ΔW = B · A    其中 A ∈ ℝ^{r×d}, B ∈ ℝ^{d×r}
  r ≪ d（rank，通常 8-64）

前向传播：h = (W + ΔW)x = Wx + BAx

参数量对比（以 d=4096, r=16 为例）：
  全量微调 ΔW：4096 × 4096 = 16.7M 参数/层
  LoRA (A+B)：4096×16 + 16×4096 = 131K 参数/层
  压缩比：128x！

初始化：
  A ~ N(0, σ²)   （随机初始化）
  B = 0           （零初始化，保证训练开始时 ΔW=0）
  缩放因子：α / r（α 通常设为 r 的 1-2 倍）
🔥 QLoRA

QLoRA = 量化基础模型 + LoRA。基础模型以 4-bit NF4 格式加载（省内存），只训练 LoRA 的 A/B 矩阵（FP16/BF16）。这就是你在 32GB MacBook 上能微调 7B 模型的原因。

D10MoE 架构与 KV Cache 推理优化▶

学习目标

理解两个在现代 LLM 中无处不在的工程概念：Mixture of Experts（稀疏激活）和 KV Cache（加速推理）。

📐 推导 MoE 与 KV Cache 原理
═══ Mixture of Experts (MoE) ═══
标准 FFN：y = FFN(x)（每个 token 都经过同一个 FFN）
MoE FFN：
  gate(x) = softmax(W_g · x)  → 路由概率（K 个专家）
  选择 top-k 个专家（通常 k=2）
  y = ∑ᵢ gate_i(x) · FFNᵢ(x)（只计算被选中的专家）
例：Mixtral 8×7B → 8 个专家，每次激活 2 个
  总参数 46.7B，但每个 token 只用 ~13B → 推理快，效果好

═══ KV Cache ═══
自回归生成时，第 t 步需要：
  Attention(q_t, [k₁,...,k_t], [v₁,...,v_t])
观察：k₁...k_{t-1} 和 v₁...v_{t-1} 之前已经算过了！
KV Cache：缓存所有已计算的 K 和 V，每步只需要：
  1. 计算新 token 的 q_t, k_t, v_t
  2. 把 k_t, v_t 追加到缓存
  3. q_t attend 到整个缓存
内存占用：2 × n_layers × d_model × seq_len × dtype_size
  7B 模型 4096 context: ≈ 1GB

D11CLIP：对比学习对齐视觉与语言▶
📊 CLIP 双塔对比学习

学习目标

CLIP 是几乎所有多模态大模型的视觉编码器来源。学完今天你应能：(1) 讲清「双塔 + 共享空间 + 对比学习」三件套；(2) 默写 InfoNCE 损失并解释温度 τ 的作用；(3) 说清为什么 batch size 是关键、为什么要 L2 归一化；(4) 解释 zero-shot 分类的原理；(5) 用 open_clip 跑一次 zero-shot 推理。

一、动机：怎么让图像和文本「可比较」

图像和文本是两种完全不同的模态，无法直接比较。CLIP 的思路极其干净：用两个编码器各自把图像、文本映射到同一个 d 维向量空间，在这个空间里，「一张猫的图」和「a cat」这句话的向量应该挨得很近。一旦图文进入同一空间，「图像理解」就被转化成了「向量检索」。

🔥 CLIP 三件套

① 图像编码器（ViT-L/14 或 ViT-bigG）：图像 → 一个全局图像向量 v。

② 文本编码器（Transformer）：文本 → 一个全局文本向量 u。

③ 对比学习：在一个 batch 的 N 对图文上，构造 N×N 相似度矩阵，拉近对角线（匹配对）、推远其余（负样本）。两个向量都做 L2 归一化，相似度就是余弦相似度。

对多模态大模型而言，CLIP 真正值钱的是「图像编码器」——它产出的视觉特征天然和语言对齐，后面 LLaVA 只需一个小 projector 就能接上 LLM。

💡 和你的 CV 直觉对接

这其实就是你熟悉的度量学习 / 表征对齐：把 triplet loss 里「锚-正-负」的思路,扩展成「用整个 batch 内所有不匹配对当负样本」。CLIP 没有发明新数学,它的赢点是4 亿图文对 + 超大 batch——数据和规模再次胜过技巧。

二、对比损失（InfoNCE）

📐 推导 CLIP 对比学习损失 InfoNCE（务必能默写）
一个 batch：N 对 (image, text)
图像编码器：v_i = f_img(x_i) / ‖·‖     （L2 归一化到单位球）
文本编码器：u_j = f_txt(t_j) / ‖·‖

相似度矩阵（余弦相似度 × 温度）：
  S_ij = exp(τ) · (v_i · u_j)          τ 可学习，等价于 1/temperature

Image→Text（每张图在 N 个文本里找正确那条）：
  L_i2t = - (1/N) ∑_i log [ exp(S_ii) / ∑_j exp(S_ij) ]   ← softmax 取行
Text→Image（每条文本在 N 张图里找正确那张）：
  L_t2i = - (1/N) ∑_j log [ exp(S_jj) / ∑_i exp(S_ij) ]   ← softmax 取列
总损失：
  L = (L_i2t + L_t2i) / 2              对称交叉熵

温度 τ 的作用：
  τ 大 → 分布更尖锐 → 更强调最难的负样本（但易不稳）
  CLIP 把 τ 设为可学习，并裁剪上限防止爆炸

为什么 batch 越大越好？
  分母是「该样本 vs batch 内所有负样本」，
  N 越大 → 负样本越多 → 对比信号越强。
  CLIP 原论文 batch size = 32768（多机多卡同步）！

三、动手：用 CLIP 做 zero-shot 分类

CLIP 不需要在你的任务上训练,就能分类——把每个类别写成一句话,看哪句和图像向量最近。这就是 zero-shot。

# pip install open_clip_torch torch pillow import open_clip, torch from PIL import Image model, _, preprocess = open_clip.create_model_and_transforms( "ViT-L-14", pretrained="openai") tokenizer = open_clip.get_tokenizer("ViT-L-14") model.eval() image = preprocess(Image.open("cat.jpg")).unsqueeze(0) # (1,3,224,224) labels = ["a photo of a cat", "a photo of a dog", "a photo of a car"] text = tokenizer(labels) with torch.no_grad(): img_f = model.encode_image(image) # (1, 768) txt_f = model.encode_text(text) # (3, 768) img_f /= img_f.norm(dim=-1, keepdim=True) # L2 归一化（关键！） txt_f /= txt_f.norm(dim=-1, keepdim=True) probs = (100.0 * img_f @ txt_f.T).softmax(-1) # 余弦相似度 → 概率 for label, p in zip(labels, probs[0]): print(f"{label:24s} {p.item():.3f}")

D12SigLIP 与视觉编码器的选择▶
📊 SigLIP vs CLIP：归一化方式之别

学习目标

CLIP 用 softmax 对比,分母要看「整个 batch」,于是必须超大 batch + 跨卡同步,很贵。SigLIP 把它换成逐对 sigmoid,一举解决。学完今天你应能：(1) 说清 softmax 对比「贵在哪」;(2) 默写 SigLIP 的 sigmoid loss、解释 bias 项;(3) 说清「为什么 sigmoid 省掉了跨卡同步」;(4) 知道主流 MLLM 各用什么视觉编码器、怎么选;(5) 用 HF 跑一次 SigLIP(记住推理用 sigmoid 不是 softmax)。

一、动机：CLIP softmax 贵在哪

CLIP 的损失分母是 ∑_j exp(S_ij)——要对「这张图 vs batch 里所有文本」做归一化。batch 越大效果越好,但 batch 大到几万时,负样本分散在几十张卡上,每步都要 all-gather 把所有特征拉到一起算 softmax,通信开销巨大。SigLIP 的洞察:把「N 选 1 的多分类」换成「N² 个独立的是/否二分类」,每个格子只看自己,归一化消失,跨卡同步也就没了。

🔥 SigLIP 的核心改动

双塔结构和 CLIP 完全一样(图像编码器 + 文本编码器 + 相似度矩阵),唯一变的是 loss：对相似度矩阵的每一个格子独立做 sigmoid 二分类——对角线 label=+1(是匹配对),其余 label=−1(不是)。没有 softmax,所以不需要看到「整行/整列」,各卡算各自的局部矩阵即可。

💡 一句话直觉

CLIP 问的是「在这一排里哪一个是对的?」(必须看全排);SigLIP 问的是「这一对是不是对的?」(只看这一对)。把排他的多分类拆成独立的二分类,通信成本就从 O(全 batch) 降到 O(本地)。

二、SigLIP 损失

📐 推导 Sigmoid 对比损失（对比 CLIP 的 softmax）
归一化向量：x_i = 图像特征，y_j = 文本特征（都 L2 归一化）
相似度：    s_ij = x_i · y_j

标签：z_ij = +1 (i = j，匹配对)
            −1 (i ≠ j，负样本)

SigLIP loss（每个格子独立的 logistic 二分类）：
  L = - (1/N) ∑_i ∑_j  log σ( z_ij · ( t · s_ij + b ) )
      其中 σ 是 sigmoid，t 是温度，b 是可学习 bias

为什么需要 bias b？
  矩阵里负样本(N²−N 个)远多于正样本(N 个)，
  初期模型会把所有对都判成「负」。
  b 给一个初始偏置，缓解这种极端不平衡，训练更稳。

对比 CLIP（softmax）：
  CLIP:    L_i = -log[ exp(s_ii) / ∑_j exp(s_ij) ]   ← 分母含整行 → 需全 batch
  SigLIP:  每个 (i,j) 独立 → 分母消失 → 各卡只算本地块

收益：
  ① 省掉跨卡 all-gather，通信大降
  ② 小 batch 也能训得好（不再依赖超大 batch）
  ③ 效果与 CLIP 持平甚至更好
🔥 主流 MLLM 的视觉编码器怎么选

LLaVA-1.5：CLIP ViT-L/14 (336px) · Qwen-VL：ViT-bigG (OpenCLIP) · InternVL：InternViT-6B(自训练超大 ViT) · PaliGemma / 新一代：SigLIP ViT-So400m。
选择逻辑:要分辨率高(看清小字/细节) → 336/448px;要训练省 → SigLIP;要视觉能力天花板 → 自训大 ViT(InternViT)。趋势:SigLIP 正在取代 CLIP 成为默认视觉塔。

三、动手：跑一次 SigLIP（注意用 sigmoid！）

# pip install "transformers>=4.39" torch pillow from transformers import AutoProcessor, AutoModel import torch from PIL import Image model_id = "google/siglip-base-patch16-224" model = AutoModel.from_pretrained(model_id) processor = AutoProcessor.from_pretrained(model_id) image = Image.open("cat.jpg") texts = ["a photo of a cat", "a photo of a dog", "a photo of a car"] inputs = processor(text=texts, images=image, padding="max_length", return_tensors="pt") with torch.no_grad(): out = model(**inputs) logits = out.logits_per_image # (1, 3) probs = torch.sigmoid(logits) # ← SigLIP 用 sigmoid，不是 softmax！ for t, p in zip(texts, probs[0]): print(f"{t:24s} {p.item():.3f}") # 每个概率独立，不强制和为 1

一、图像怎么变成 token

LLM 只认 token 序列。把图像变 token 的标准流程:切 patch → ViT 编码 → 每个 patch 成一个视觉 token → connector 对齐到 LLM 维度 → 和文本 token 拼成一队。和 D14 的 LLaVA 一脉相承,这里我们把镜头拉近,专门盯住「token 数量」这件要命的事。

🔥 视觉 token 流程四步

① 切 patch + ViT:224px 图 →(224/14)²= 256 token;336px → 576;448px → 1024。

② 动态分辨率:高清图按比例切成多个 tile,每个 tile 各 576~1024 token → 总数 ×tile 数,轻松上千。

③ Connector:把视觉 token 既对齐到 LLM 维度(如 1024→4096),又压缩数量(可选)。

④ 拼接:压缩后的视觉 token 与文本 token 排成一个序列送入 LLM。

💡 和你的超分/图像复原经验对接

「分辨率高看得清,但 token 太多算不动」本质就是你熟悉的 信息量 vs 计算成本 的 trade-off。Pixel Shuffle 把空间分辨率「折叠」进通道维(空间↓、通道↑),正是超分里 sub-pixel convolution 的同款操作——你已经会了。

二、token 数量：算给你看

📐 推导 视觉 token 数量与压缩（工程上最要命的数）
单张图 token 数：
  N = (img_size / patch)²
  224 / 14 = 16  → 256
  336 / 14 = 24  → 576
  448 / 14 = 32  → 1024

动态分辨率（高清图切 tile，如 InternVL / LLaVA-NeXT）：
  把图按长宽比切成 k 个 448×448 tile（再加一张缩略全图）：
  N_total = k × 1024 (+1024)
  例：切成 4 tile → 4×1024 = 4096 个视觉 token  ⚠ 爆炸

为什么是大问题？
  视觉 token 和文本 token 抢同一个 context window，
  4096 个视觉 token ≈ 把上下文塞满，且 attention 是 O(L²)，
  序列翻倍 → 计算翻 4 倍 → 推理显著变慢。

四种 Connector / 压缩方案：
  ① MLP（LLaVA）       ：只对齐维度，不压数量（最简单）
  ② Pixel Shuffle      ：相邻 2×2 token 折叠进通道，数量 ÷4、维度 ×4
     （InternVL / LLaVA-NeXT；空间↓ 通道↑，几乎不丢信息）
  ③ Perceiver Resampler：用固定数量 query 做 cross-attention，
     把任意多 token 压到固定 K 个（Flamingo）
  ④ Q-Former           ：可学习 query + 多层注意力提取信息（BLIP-2）

口诀：MLP 保真不压 → 数量爆；Resampler/Q-Former 压到固定数 → 可能丢细节；
      Pixel Shuffle 折叠 → 折中，当前最流行。

一、动机：让「只懂文字」的 LLM「看见」图像

LLM 的输入是一串 token 的词向量（embedding 序列），而图像是连续像素。要让 LLM 处理图像，核心问题只有一个：找一个「翻译官」，把图像变成 LLM 词向量空间里的若干个「伪词」，和文本词向量拼在一起喂进去。LLaVA 给出的答案简单到令人意外——这个翻译官就是一个 MLP。

🔥 LLaVA 三件套

① 视觉编码器（CLIP ViT-L/14，❄️ 冻结）：把图像切成 patch，编码成一串视觉特征 Z_v ∈ ℝ^(576×1024)。用的是 CLIP 倒数第二层的 grid 特征（不是 CLS）。

② Projector / 连接器（🔥 要训练）：一个把 1024 维视觉特征映射到 LLM 词向量维度 4096 的小网络。LLaVA-1 是单层 Linear，LLaVA-1.5 换成 2 层 MLP。它是整个架构里唯一为「对齐」而新增的部件。

③ 大语言模型（Vicuna / Llama）：把这 576 个「视觉词」当外语词，和文本词拼成一个序列，自回归生成回答。

没有 cross-attention，没有 Q-Former。就这么三件套，却在当年打穿了一堆复杂架构——说明瓶颈不在「怎么融合」，而在「数据质量 + LLM 本身够强」。

💡 和你的 CV 直觉对接

ViT 把图像变成 patch token 序列，你已经很熟。LLaVA 做的事，本质就是你做过无数次的「特征空间对齐」——只不过这次是把 CLIP 的视觉特征，用一个线性/MLP 投影对齐到 LLM 的词向量空间。把它类比成「域适配里的一层 projection head」，直觉立刻通了。

二、数据怎么流过模型（维度全程跟踪）

📐 推导 从一张图到一段回答的完整维度变换（务必能默画）
输入：一张 RGB 图像 X_v ∈ ℝ^(336×336×3)

① 视觉编码（CLIP ViT-L/14，patch=14）
   patch 数 = (336/14)² = 24×24 = 576
   取倒数第二层 grid features（去掉 [CLS]）：
   Z_v = g(X_v) ∈ ℝ^(576 × 1024)        1024 = CLIP ViT-L 隐藏维

② Projector：视觉维度 → LLM 词向量维度
   LLaVA-1（线性）:  H_v = W · Z_v ,         W ∈ ℝ^(4096 × 1024)
   LLaVA-1.5（MLP）: H_v = W₂ · GELU(W₁ · Z_v)
   得 H_v ∈ ℝ^(576 × 4096)               4096 = Vicuna-7B 隐藏维
   —— 576 个「视觉词向量」，与文本词向量同维、可直接拼接

③ 文本走正常 embedding
   "USER: <image>\n描述这张图 ASSISTANT:"
   → token ids → H_t ∈ ℝ^(L × 4096)

④ 拼接成一个序列（关键！见下方机制）
   把文本里的 <image> 占位符，替换成 ② 的 576 个视觉向量：
   H = [ H_前 ; H_v(576) ; H_后 ] ∈ ℝ^((L-1+576) × 4096)

⑤ LLM 自回归生成回答
   p(X_a | X_v, X_q) = ∏_i p(x_i | H, x_<i)
   视觉 token 通过 self-attention 被每个文本 token「看到」

一句话记忆：图像 → 576 个伪词 → 和文字排成一队 → LLM 照常说话。
🔥 视觉 token 怎么「塞进」文本序列（面试必考）

输入里先放一个特殊占位符 <image>（对应一个保留 token id）。前向时：先用 LLM 的 embedding 层把文本 token 变成词向量，再把序列中那一个 <image> 位置，替换/展开成 Projector 输出的 576 个视觉向量。所以「1 个占位符 → 576 个视觉 token」，序列长度相应变长。注意：替换的是输入 embedding，不是 token id——视觉向量根本不在词表里。

📐 推导 训练目标、loss 落点与两阶段冻结策略
训练目标：标准自回归语言建模 loss，但只在「回答」上计算
  L = - ∑_{i ∈ answer} log p(x_i | H, x_<i)

  若一上来就端到端：Projector 是随机初始化，

  先用海量图文对把 Projector 训到「对齐」，再联合微调，稳得多。
💡 LLaVA-1.5 相比 LLaVA-1 改了什么

① Projector：Linear → 2 层 MLP（表达力更强）；② 分辨率 224→336（视觉 token 256→576，看得更清）；③ 训练数据加入 VQA / OCR / 学术任务，并规范了 prompt 格式。改动都很「工程」，却带来大幅提升——再次印证数据和分辨率比架构花活更关键。

二、代码精读：图像是怎么「插进」序列的

LLaVA 的灵魂在 llava/model/llava_arch.py。把下面这段(简化版)和源码对照着读,你就彻底懂了 D14 讲的「占位符替换」机制在代码里长什么样。

import torch IMAGE_TOKEN_INDEX = -200 # <image> 占位符的特殊 id（不在正常词表里） def encode_images(self, images): feats = self.vision_tower(images) # CLIP ViT -> (B, 576, 1024) return self.mm_projector(feats) # MLP -> (B, 576, 4096) def prepare_inputs_labels_for_multimodal(self, input_ids, labels, images): image_features = self.encode_images(images) # (B, 576, 4096) new_embeds, new_labels = [], [] for ids, lab, feat in zip(input_ids, labels, image_features): emb = self.embed_tokens(ids.clamp(min=0)) # 文本 -> (L, 4096) pos = (ids == IMAGE_TOKEN_INDEX).nonzero()[0].item() # 找 <image> # 在 embedding 层把 1 个占位符展开成 576 个视觉向量 emb = torch.cat([emb[:pos], feat, emb[pos+1:]], dim=0) # 视觉 token 的 label 设为 -100（不计 loss） vlab = torch.full((feat.size(0),), -100, device=lab.device) lab = torch.cat([lab[:pos], vlab, lab[pos+1:]], dim=0) new_embeds.append(emb); new_labels.append(lab) return pad_and_stack(new_embeds, new_labels) # 处理变长 + attention_mask
🔥 四个必看的点

① encode_images():vision_tower(CLIP) + mm_projector(MLP),出 (B,576,4096)。② IMAGE_TOKEN_INDEX = -200:负数 id,故意不在词表里——所以必须在 embedding 层替换,不能走正常 embedding。③ 合并发生在 prepare_inputs_labels_for_multimodal():用 torch.cat 把视觉向量插进占位符位置。④ 视觉 token 的 label=-100:自回归 loss 不算在图像上(呼应 D14 的 loss 落点)。

D17Qwen-VL 系列：中文多模态的标杆▶

学习目标

Qwen-VL 在中文多模态领域几乎是标杆。理解它的架构特点和训练数据策略。

📐 推导 M-RoPE（Multimodal RoPE，Qwen2-VL 的创新）
标准 RoPE：每个 token 有 1D 位置 m
M-RoPE：每个 token 有 3D 位置 (t, h, w)
  t = 时间维度（视频帧号）
  h, w = 空间维度（patch 的行列位置）

将 d 维 head 分成三段：
  dim[0:d/3]    → 用 t 做 RoPE（时间位置）
  dim[d/3:2d/3] → 用 h 做 RoPE（垂直位置）
  dim[2d/3:d]   → 用 w 做 RoPE（水平位置）

对于文本 token：t=h=w=当前序列位置（退化为标准 RoPE）
对于图像 token：t=固定，h/w=patch 在图像中的行列坐标

这样模型天然知道「这个 patch 在图像的左上角还是右下角」。

📐 推导 Flash Attention 核心思想
标准 Attention 的内存瓶颈：
  S = QKᵀ ∈ ℝ^{N×N}     ← N=4096 就要 64MB
  P = softmax(S)
  O = PV

Flash Attention：
  不存储完整的 S 和 P 矩阵
  把 Q, K, V 分成 blocks，在 SRAM（高速缓存）中计算
  利用 online softmax 技巧避免需要全局 max

结果：内存从 O(N²) 降到 O(N)，速度提升 2-4x
