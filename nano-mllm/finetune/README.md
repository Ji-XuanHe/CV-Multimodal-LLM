# 后训练 / 强化学习 —— 给初学者的「能跑的」教程

> 很多人卡在「RLHF / PPO / GRPO 到底在干嘛」。这一节用**能直接运行**的最小代码，
> 把后训练（post-training）一次讲透。每节配一个 `python` 命令，跑一下就懂。

预训练（pretraining）只让模型学会「**续写**」。要让它**听指令、对齐人类偏好、会推理**，
靠的是**后训练**。后训练分两步走：先 SFT，再 RL（或 DPO）。

```
预训练（学知识，会续写）
   └─► SFT 监督微调（学格式，会听指令）          ← finetune/sft.py
          └─► 偏好对齐：二选一
                ├─ RLHF / PPO / GRPO（用奖励强化）  ← finetune/toy_rlhf.py ★
                └─ DPO（不用 RL 的捷径）            ← finetune/dpo.py
```

---

## 1. SFT：先学会「听指令」 → `python finetune/sft.py`

**大白话**：老师傅手把手教「遇到这类问题，就该这么答」。

**唯一的技术点**：loss **只算回答（response）**，不算问题（prompt）。把 prompt 部分的
label 设成 `-100`（被 CrossEntropy 忽略）就行。运行 `sft.py` 会验证：SFT loss 严格
等于「只对回答段算的交叉熵」。

> SFT 之后，模型会听指令了，但它**不知道两个都合规的回答里哪个更好** —— 这就要靠下面的对齐。

---

## 2. 为什么需要 RL：奖励从哪来

**大白话**：SFT 是「抄标准答案」，但很多时候**没有唯一标准答案**（哪个回答更有帮助？
哪句话更礼貌？），只有「这个比那个好」的**偏好**。RL 让模型**自己生成 → 拿奖励 → 调整**。

奖励 `r` 有两种来源，这是理解整条线的关键分叉：

| 奖励来源 | 怎么打分 | 代表 | 优缺点 |
|---|---|---|---|
| **学出来的 Reward Model** | 用人类偏好对训练一个打分模型 | InstructGPT、经典 RLHF | 通用，但贵、会被「钻空子」(reward hacking) |
| **规则 / 可验证奖励 (RLVR)** | 直接写规则：答案对不对、代码跑不跑、格式合不合 | DeepSeek-R1、数学/代码推理 | 便宜、稳、不易被 hack；适合有标准答案的任务 |

`toy_rlhf.py` 用的是**第二种（规则奖励）**，因为它最干净、最好理解，也是当下训练
推理模型最火的范式。

---

## 3. 动手：从零跑一次 GRPO → `python finetune/toy_rlhf.py` ★

这是本节的核心。~50 行纯 numpy，把 RL 后训练的 4 个零件凑齐，运行就能看到
**「无任何标注，只给一个规则奖励，模型自己学会高奖励行为」**：

```
step   0  平均奖励 1.53/6   (随机基线 ≈ 1.50)
step  40  平均奖励 5.00/6
step  80  平均奖励 5.81/6
step 120  平均奖励 5.95/6
训练后每位置最可能字符: 'eaeaea'  -> 几乎全是元音，学会了高奖励行为 ✅
```

**4 个零件 ↔ 真正的 RLHF/GRPO**：

1. **策略 π** = 模型本身（toy 里简化成 logits 表）
2. **rollout** = 让策略采样一批完成（就像 LLM 自回归生成）
3. **奖励 r** = 一个**规则**给每条完成打分（这里：元音越多越好）
4. **优势 advantage** = **GRPO 的精髓**：不训练价值网络(critic)，而是同一题采 G 条，
   `advantage = (r − 组内均值) / 组内标准差` —— 谁高于这组平均，谁就「相对更好」
5. **KL 拴住参考模型** = 别为了刷奖励跑飞（reward hacking）。`β` 越大越保守

把「元音个数」换成「数学题答对没」「代码跑通没」，**这就是训练 o1 / R1 这类推理模型的 RL**。

### PPO vs GRPO（一句话区别）

- **PPO**：要额外训一个**价值网络(critic)**来估计「基线」，再算优势。重、占显存。
- **GRPO**：干脆**采一组、用组内平均当基线** —— 省掉 critic，简单稳定，DeepSeek 用它训出 R1。
  （`toy_rlhf.py` 实现的就是 GRPO 的这个核心。）

### 「先 SFT 后 RL，奖励先变差再变好」

跑真实 RL 时你常会看到 reward **先下探到谷底、再回升反超**（hockey-stick 曲线）。
别在谷底误判「训崩了」—— 这是 SFT 把策略压得太确定、RL 早期探索偏离分布所致，
盯住 KL / 熵 / 回答长度，熬过去就好（详见路线图 D06）。

## 4. DPO：不想搞 RL？走捷径 → `python finetune/dpo.py`

**大白话**：RL 要「裁判（reward model）+ 强化学习」，又贵又难调。DPO 用数学证明
「最优策略和裁判打分有固定换算关系」，于是**把裁判直接消掉**，变成一道简单的
「二选一」判断题：给一对〈好回答, 坏回答〉，直接拉高好的、压低坏的。

运行 `dpo.py` 会看到：策略「更偏好好回答」时 loss 小，反之 loss 大。
**现在大多数开源模型用 DPO 或其变体**（简单、稳、不用 RL）。

> 取舍：DPO 简单稳定、适合「有成对偏好数据」；GRPO/RL 上限更高、适合「有可验证奖励
> （数学/代码/规则）」的推理任务。两条路都要懂。

---

## 5. OPD：最新——在策略 + 稠密信号（2025 最火的蒸馏配方）→ `python finetune/opd.py` ★

**大白话**：SFT 是「抄老师的标准答案」（在老师走过的路上学），但你自己考试一旦走偏，就到了
老师没教过的地方，错上加错（exposure bias）。RL 是「自己做题、只告诉你最后对不对」（信号太稀）。
**OPD = 自己做题（on-policy），但老师在你写的每一个字上都告诉你「这一步正确的分布长啥样」**
（稠密）—— 既在你真会遇到的状态上学，又每步都有满满的监督。

**机制**：学生【自己生成】序列，教师对【每个 token】给出完整分布，学生用 **reverse-KL** 匹配它。
- vs SFT / 离策略蒸馏：OPD 在【学生自己的轨迹】上学 → 治 exposure bias；
- vs RL / GRPO：OPD 每个 token 都有【完整分布】监督，不是一整条才一个标量奖励。

**为什么火**：数学推理上 OPD 能用 **≈RL 的 1/10 算力**达到同等水平（Thinking Machines 报告：
AIME'24 74.4%，1800 vs 17920 GPU 时；7–10× 更少梯度步），已被多家产线当作 SFT 之后的主蒸馏阶段。

**跑一下** `python finetune/opd.py`：学生在「计数」任务上、靠在自己 rollout 的状态上匹配教师逐 token
分布，**reverse-KL 从 0.74 掉到 ~0.001**、学会教师规则 —— 这就是 OPD 的核心。

> 何时用哪个：有强教师、想便宜地逼近它 → OPD；有可验证奖励、想突破教师上限 → GRPO；
> 只有成对偏好 → DPO；最开始让模型听话 → SFT。

参考：GKD（arXiv:2306.13649）· MiniLLM（arXiv:2306.08543）· MLLM 上的 OPD（arXiv:2606.09091）·
Thinking Machines Lab, *On-Policy Distillation*（2025, 博客）。

## 一句话总结

| 阶段 | 目的 | 跑这个 |
|---|---|---|
| SFT | 学会听指令（只学回答） | `python finetune/sft.py` |
| RL/GRPO | 用奖励把行为推向「更好」（无需标注，规则即奖励） | `python finetune/toy_rlhf.py` ★ |
| OPD | 在策略 + 稠密：自采样、教师逐 token 蒸馏（≈10× 省于 GRPO） | `python finetune/opd.py` ★ |
| DPO | 不搞 RL 的对齐捷径（成对偏好直接优化） | `python finetune/dpo.py` |
| LoRA | 让上面这些在你的显卡上跑得起（只训低秩旁路） | `python finetune/lora.py` |

跑完这 5 个，你就**真的理解**了「后训练 / SFT / RLHF / GRPO / OPD / DPO」—— 不是听过，是跑过。
